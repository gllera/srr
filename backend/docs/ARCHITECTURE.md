## Module System (`mod/`)


Pipeline per-feed during fetch. Factory pattern: `New()` returns a fresh stateful processor; each built-in registers a `func() Processor` factory that runs once per `New()` so it can capture per-instance state (compiled policies, a shared HTTP client). A built-in processor is `mod.Processor` = `func(context.Context, Params, *RawItem) error` (the ctx is the per-fetch context, threaded through `Module.Process`); most built-ins ignore the ctx, but network-bound ones like `#readability` use it for cancellation/deadline.

**Two step forms, one namespace (`session.go`, FET11 2026-07-26).** A built-in that walks HTML registers a `mod.DOMProcessor` = `func(ctx, Params, *RawItem, *html.Node) (changed bool, err error)` via `RegisterDOM`, and is handed the item's ALREADY-PARSED content body instead of its string. The per-item `Session` (`Module.NewSession(i)`, driven by `processItem`) owns that parse: it parses on first use, hands the same `*html.Node` to every DOM step in a contiguous run, and materializes the string only at a **boundary** — a string-form step (`#sanitize`, `#minify`, `#readability`, `#filter`, any shell mod, all of which read `RawItem.Content`) or `Close`. A step reporting `changed=false` is what keeps a no-op pass BYTE-IDENTICAL, the contract each HTML mod used to enforce with its own verbatim return; a step must neither read nor write `i.Content` (stale while an earlier step's changes are unrendered, and overwritten by the next flush) — the body is the content. `Session.Rev()` counts content mutations from both forms, which is how the post-pipe language retry asks "did anything change?" without materializing. DOM steps today: `#enclosure`, `#unlazy`, `#untrack`, `#dedupmedia`, `#embed`, `#selfhost`. `Module.Process` (one token, standalone — used by tests) is a one-token session, so a built-in behaves identically either way, and `Builtins()`/`Validate` treat the two registries as one namespace (a DOM step validates against its own empty body). Measured on a rich pipe over an ~11 KB article: **−31% CPU, −46% bytes allocated** per item (`bench_dom_test.go` pins the numbers and the fixture); the always-on absolutizer + language stamp make the string-only pipe win one parse too. The end-of-pipeline asset upload (`RewriteAttrs`) stays outside the session on purpose — it is a separate concurrent phase, gated by `HasAssetMarkers`, and keeping every item's DOM alive across the batch to fuse it would trade CPU for memory the wrong way.

**File layout** — `main.go` holds the engine (registry + `Module`/`Process` dispatch), the `RawItem` wire types, and the external/shell-module exec; `session.go` holds the DOM step form and the one-parse content session (`DOMProcessor`, `RegisterDOM`, `resolveStep`, `Session`). Support helpers carry a `helper_` filename prefix (`helper_params.go`, `helper_assets.go`, `helper_ssrf.go` — the latter exports `SafeTransport`, the SSRF-guarded `*http.Transport` used by `#readability`) to set them apart from the built-in module files, which are named for the module itself (`sanitize.go`, `minify.go`, `readability.go`, each with a matching `_test.go`). `secrets.go` holds `SetSecrets`/`WithSecretScopes`/`SubprocessEnv(ctx)`/`AllScopes`/`MissingScopes` — the scoped secret store and the process-env⊕granted-scopes merge (granted secrets win, deduped, sorted; later grant wins a cross-scope name collision), computed per exec from the ctx-carried grant by both `Module.Process` and `ingest.Fetcher.Fetch`'s external paths (an unstamped ctx merges nothing — fail-closed).

**Module parameters** — a pipeline token may carry `key=value` options after the name, e.g. `#readability timeout=30s maxbody=16MiB`. `Module.Process` splits the token on whitespace; when the first field is a registered built-in it parses the rest into `mod.Params` (see `helper_params.go`) and dispatches internally, otherwise the original string runs as a shell command (so shell commands with spaces/`=` are untouched). The param split is **quote-aware** (`splitParamFields`): a double-quoted span keeps its spaces and drops the quotes, so a value with spaces stays one param (`ua="Mozilla/5.0 (X11)"`); an unterminated quote is a hard error, and there is no escape for a literal `"`. Built-ins read options via typed accessors with a default for the absent case — `Params.Duration(key, def)`, `Params.Bytes(key, def)` (sizes accept `B`/`KB`/`MB`/`GB` decimal or `KiB`/`MiB`/`GiB` binary; bare = bytes), `Params.String(key, def)` (verbatim value; explicitly empty = hard error) — and call `Params.only(allowed...)` to reject unknown keys. A malformed value or unknown key is a hard error (loud config feedback), distinct from a module's per-article fail-open behaviour; modules that take no options reject any param. Parameters are parsed per-item but the cost is negligible. External (shell) modules don't get parsed params — they receive their args on the command line.

- `#sanitize` — bluemonday, content-only. Allows `<audio>` (`src`/`controls`/`preload`, mirroring `<video>`) so `#selfhost` can self-host audio.
- `#minify` — tdewolff/minify, content-only.
- `#readability` — for feeds that syndicate only a teaser/summary: HTTP-GETs the item's `Link` (honest keyword-free UA — `+full-text-extractor` was dropped 2026-07-03, keyword-scanning WAFs 406 on "extractor"; default 20s timeout, 8 MiB body cap) and replaces `Content` with the article's main body extracted via `go-shiori/go-readability`. Tunable per pipeline position via `timeout=` (Go duration), `maxbody=` (byte size), `ua=` (request User-Agent — quote it, real UAs have spaces; some WAFs 406 on UA keywords, e.g. blogdechollos.com blocks any UA containing "extractor") and `selector=` (CSS selector group via `cascadia`; when set, the matches' HTML — every match in document order, inner HTML per match, childless matches like `<img>` render the element itself, matches nested in an earlier match are folded in — replaces the readability heuristic entirely: the per-site escape hatch for pages whose short genuine body loses the candidate scoring to text-dense sidebar/widget chrome (deal blogs), and via comma groups also the way to stitch disjoint blocks (hero image + body) into one article; a selector miss keeps the original content and WARNs, it never falls back to the heuristic), e.g. `#readability ua="Mozilla/5.0 (compatible; SRR/1.0)" selector=div.entry-content`; the timeout is enforced via a per-call `context.WithTimeout` so the shared client can carry different budgets. **Fail-open**: empty/invalid link, non-2xx, fetch/parse error, or empty extraction all leave `Content` untouched and return nil (logged at WARN) — one bad article never fails the fetch (but a bad `timeout=`/`maxbody=` value, or an unknown param, is a hard error). Place it **before** `#sanitize`/`#minify` (e.g. recipe pipe `["#readability", "#default"]`) so the fetched HTML gets clamped to the allowed element set. Network-bound, so unlike the other built-ins it honours the fetch `context` (cancellation/deadline).
- `mod.ParseMatch` / `mod.Match` (`helper_match.go`) — not a pipeline mod: the compiled per-article predicate the keyword watchlists (`backend/watch.go`) ask their question with, sharing `#filter`'s vocabulary, `/regex/[i]` grammar, quote-aware field split and language folding so there is exactly ONE answer to "does this article look like X?". Params `title=` / `content=` / `any=` / `lang=` / `min_words=`, at least one required. Two deliberate inversions from `#filter`, each the safe direction for its verb: conditions are **AND**-ed (a rule is one description, not a list of alternatives) and `lang=` is **fail-closed** (a watch must be positive evidence, where a filter must never lose an article). Parsing lives in the CONSTRUCTOR, which makes `#filter`'s "parse every parameter before evaluating any condition" rule structural rather than a hand-held ordering. Note for both: a pattern with a literal space needs a metacharacter or quotes around the WHOLE value, delimiters included (`any="/breaking news/"`).
- `#filter` — content-based item dropping (`filter.go`). Params (all optional; item dropped if ANY condition fires): `drop_title=/regex/[i]`, `keep_title=/regex/[i]`, `drop_content=/regex/[i]`, `keep_content=/regex/[i]`, `min_words=N`, `keep_lang=en,es` (ISO 639-1 allowlist over the item's `i.Lang` — the pre-pipe detection stamp or a declared value; **no detection of its own**, and **fail-open**: empty Lang keeps the item; codes validated against `validLangCode`, and BOTH sides folded through `normalizeLang` so `EN`/`en-US`/`en` are one code — a wire-declared `"ES"`/`"es-ES"` compared raw against a lowercased set dropped every item in the feed. A **macrolanguage** code expands config-side via `langMacro` to every variety detection can report under it: `no` admits `no`/`nb`/`nn`, since whatlanggo only ever classifies the varieties, and folding `no` to one of them silently discarded a Norwegian feed's Nynorsk half). On a match sets `i.Drop=true; return nil`. Unknown params / bad regex / bad int / unknown language code are hard errors. **Every present param is parsed before ANY condition is evaluated**: `Module.Validate` validates by running the processor against an empty sentinel item, so a firing condition returning early used to let a malformed *later* param escape config validation entirely and only surface per-item at fetch — where a pipeline error merely drops the article with a warning, so the feed silently ingested nothing. Does NOT mutate GUID/Published/Title/Content/Link/Lang.
- `#dedupmedia` — duplicate-media removal (`dedupmedia.go`): an article never shows the same picture (or video/audio) twice — the best copy survives. Groups `<img>`/`<video>`/`<audio>` by normalized file identity (`mediaFileID`: scheme + query/fragment ignored, WordPress `-WxH` size suffix stripped, `iN.wp.com` Photon proxy unwrapped; identity is per element type — an `<img>` and a `<video>` off one URL never merge) and removes all but the richest copy per group (`dedupScore`: canonical un-suffixed/un-proxied URL > alt text > declared pixel area > attribute count; ties keep document order), pruning wrapper chains a removal leaves without text or keep-worthy elements (`<a>`/`<p>`/`<figure>` → gone; `dedupKeepTags` keep them alive). Inline-glyph images are exempt (`isMediaGlyph`) — repetition is meaningful there: emoji classes (`emoji`/`wp-smiley`/`smiley`), `height: 1em`-style, `s.w.org/images/core/emoji` URLs, ≤2-rune emoji alt, both sides ≤ 96px declared, blank/spacer/pixel/placeholder/loading file names. No params (`p.only()`). Pure CPU, never fails an item: unparseable content and no-op passes return verbatim (no re-render). **Place BEFORE `#sanitize`** (`["#dedupmedia", "#default"]`) so the glyph heuristics still see the class/style attributes the sanitizer strips. Motivating case: WordPress "featured image in feed" plugins prepending a copy of an image the body repeats (finofilipino.org — every post shipped its image twice).
- `#unlazy` — lazy-load recovery (`unlazy.go`): promotes the real URL out of `data-src`-style attributes (`lazySrcAttrs`, URL-shaped values only — a boolean `data-lazyload="true"` never becomes a src) into `src` on `<img>`/`<video>`/`<audio>`; an `<img>` whose src is still missing or a placeholder (`lazyPlaceholderRe`: data URIs, about:blank, 1x1/spacer/loading names) takes the best `srcset`/`data-srcset` candidate (largest width descriptor, else density, else first) — a genuine src is never overridden by srcset; `<noscript>` fallbacks contributing an image the document doesn't already show (by `mediaFileID` identity) are unwrapped in place, redundant ones dropped (the parser treats noscript children as raw text, so the payload is re-parsed). No params (`p.only()`). Pure CPU, fail-open, verbatim no-op. **Place BEFORE `#sanitize`** — after it the `data-*` attributes holding the real URLs are gone. Essential in pipes using `#readability` (live article pages are where lazy-load markup comes from; without this they publish with blank/1-px images).
- `#embed` — iframe-to-link conversion (`embed.go`): `#sanitize` deletes `<iframe>` wholesale, so a post built around an embed publishes with its point silently missing. Rewrites known providers (`classifyEmbed`: YouTube incl. shorts + nocookie + protocol-relative — `/embed/videoseries` playlists excluded; Vimeo `player.vimeo.com/video/<digits>`; Dailymotion classic + `geo.dailymotion.com/player.html?video=`; Spotify `open.spotify.com/embed/*`; Streamable `/e|o|s/<id>`; and, via one per-provider helper each, TikTok `embedTikTok` (`/embed/v2/<digits>`, `/embed/<digits>`, `/player/v1/<digits>`), Twitch `embedTwitch` (`player.twitch.tv?video=<digits>` with an optional `v` prefix → `/videos/<id>`, `?channel=<login>`, `clips.twitch.tv/embed?clip=<slug>`; a `collection=` player has no single target and stays unrecognized), SoundCloud `embedSoundCloud` (`w.soundcloud.com/player?url=` — only when that param parses as an http(s) URL on `soundcloud.com`, linking the re-serialized parse, never the raw string; `api.soundcloud.com` track refs need an API call and stay unrecognized) and Bandcamp `embedBandcamp` (`bandcamp.com/EmbeddedPlayer/{album,track}=<digits>/…`)) into a `<p>` holding the derivable thumbnail (YouTube `i.ytimg.com/vi/<id>/hqdefault.jpg`, Dailymotion `/thumbnail/video/<id>`; no other provider has one) wrapped in a link, plus always a "▶"-prefixed text link (labelled by the iframe `title` attr, else "Watch/Listen on <Provider>") — the thumbnail may 404 and the frontend collapses broken images, so the target stays reachable. TikTok and Bandcamp are the two whose link is the normalized PLAYER page: their embed URLs name no author/artist, so no watch page is derivable. Every id/slug/login interpolated into an href is regexp-validated first (`embedIDRe`/`embedDigitsRe`/`embedTwitchLoginRe`) — the result renders as a link in the reader. Unknown iframes (ads included) are deliberately left for `#sanitize` to strip. No params. Pure CPU, fail-open, verbatim no-op. **Place BEFORE `#sanitize`**; composes with `#selfhost` (self-hosts the injected thumbnail).
- `#enclosure` — out-of-body media surfacing (`enclosure.go`): prepends media that rides in item metadata the body never mentions — RSS `<enclosure>`, Atom `<link rel="enclosure">`, Media RSS `media:content`/`media:thumbnail` (directly or inside `media:group`, YouTube's layout), `<itunes:image>` — as leading `<p>`-wrapped `<img>` / `<video controls>` / `<audio controls>` blocks. Reads the parsed entry from `RawItem.Raw` (type-asserts `RawFeedItem`; **no-ops for external-ingest items** and on url-less `content` entries, which are text bodies not Media RSS). Picks the best image (full images beat thumbnails, then largest declared area), first video, first audio; kind from MIME prefix, then `medium` attr, then URL extension (`enclosureExtKinds`) — YouTube's `x-shockwave-flash` content entry falls out while its thumbnail survives. Skips candidates already visible in the body (exact URL, HTML-escaped URL, or `mediaFileID` identity — a WordPress size variant counts as present); non-http(s) URLs ignored. No params. Pure CPU, fail-open, verbatim no-op. **Place BEFORE `#sanitize` and `#dedupmedia`** (`["#enclosure", "#dedupmedia", "#default"]`).
- `#untrack` — tracking-freight removal (`untrack.go`): three cleanups. (1) Beacon images: an `<img>` matching `trackerPixelRe` (feedburner `~4`, Mailchimp `list-manage.com/track/open`, `pixel.wp.com`, WordPress.com stats, GA `collect`/`__utm.gif`, Facebook `tr`, scorecardresearch, quantserve, doubleclick, Yandex) or declaring both sides ≤ 2px is removed + `pruneEmptyWrappers` — the size rule skips any `<img>` still carrying a lazy `data-src` URL (a not-yet-promoted placeholder can declare 1x1). (2) Tracking query params (`utm_*` prefix + the `trackingParams` set: fbclid/gclid/mc_eid/…) stripped from `a href`, media `src`, `video poster` (`untrackAttrs`) — remaining params keep order and encoding verbatim, non-http(s) URLs never touched, emptied query drops its `?` (fragment kept). (3) The trailing WordPress "The post … appeared first on …" footer (`wpTrailerRe`, matched whitespace-collapsed against the **last** element only — the phrase mid-article survives). No params. Pure CPU, fail-open, verbatim no-op. **Place BEFORE `#sanitize`, AFTER `#unlazy`** (`["#unlazy", "#untrack", "#default"]`).
- `#selfhost` — downloads remote `<img>`/`<video>`/`<audio>` media (src + `<video poster>`, not `<a href>`) into the run's shared cache dir and rewrites each to a `#`-marker, so the end-of-pipeline upload step peeks/converts (`SRR_ASSET_PROCESS`)/uploads it to `assets/`. Network-bound (SSRF-guarded `SafeTransport`, like `#readability`); reads the run cache dir from the fetch context (`mod.WithCacheDir`, set in `feed.go:Feed.Fetch`) and **no-ops when absent** (e.g. `srr preview`). Params: `timeout=` (default 10m), `maxbody=` (default 128MiB, **clamped to `--max-asset-size`** via the `mod.MaxAssetSize` package var so the self-host object cap is enforced here at download — an over-cap body never lands in the cache); bad/unknown param is a hard error. **Fail-open per asset**: a bad URL / non-2xx / oversize / SSRF-blocked dial / write error leaves the remote URL in place (WARN). Download dedup is URL→cache-file; upload dedup is `UploadCacheRef`'s content hash. **Place AFTER `#default`** (`["#default", "#selfhost"]`): it then downloads only sanitizer-approved media and its markers (incl. `<video poster>`) never round-trip through `#sanitize`. Limitations: with `webify` as `SRR_ASSET_PROCESS`, audio is self-hosted but not transcoded (webify is image/video only); `<source>` children stay stripped; cross-run URL cache may serve stale bytes (clear the cache dir).
- External modules: `/bin/sh -c`, stdin/stdout JSON (`RawItem`), stderr passthrough. Emitting `{"drop":true}` on stdout sets `i.Drop=true` (via the existing `json.Unmarshal(out, i)` path — no peek struct needed); subsequent pipeline steps are skipped and the item is not stored. Dropped items retain their GUID in the feed boundary. The author-facing protocol spec + a reference implementation live in `backend/README.md` (External mod protocol); the protocol tests are in `mod/main_test.go`.

#### Asset self-hosting (`assetFetcher.UploadCacheRef` + `RewriteAttrs`)

SRR self-hosts files an ingest strategy or the built-in `#selfhost` mod leaves in the run's shared cache dir: it stores them under a content-hash key (`assets/<2-hex>/<16-hex><ext>`) and rewrites the in-content reference to that key. This is **not** a pipeline module — it is the automatic end-of-pipeline step `fetchRun.uploadAssets`, run from `Feed.fetchURL`.

- Implementation `assetFetcher` (`assets.go`): `UploadCacheRef(ctx, cacheDir, localname)` returns `(key, uploadedBytes, err)` — uploadedBytes is the payload size of the Put THIS call led (0 on memo/store dedup hits and for singleflight followers, so summing it counts each stored object exactly once; it feeds `Feed.AssetBytes`). It resolves `localname` inside `cacheDir` (guards: containment via `EvalSymlinks`+`Rel`, reject non-regular/symlink), keys by `contentHashKey` (sha256 of the **original source file bytes**, with the source extension) and `Put`s only if the key isn't already in the store (`Backend.Stat` existence probe — zero-body; `size == 0` falls back to the body-carrying `Get` check, which stays authoritative for the cases a HEAD can't prove: a zero-byte stored asset, an HTTP store omitting Content-Length). The `SRR_MAX_ASSET_SIZE` cap is **enforced at download** (`#selfhost` / external ingest via `Request.MaxAssetSize`), so `UploadCacheRef` trusts the cache file and does **not** re-check the source size. It does no outbound HTTP. **Assets are never slurped**: `hashSource` hashes the cache file with one streaming `io.Copy` and keeps the bytes only below `assetInMemoryMax` (1 MiB, a test-shrinkable var) — above it the payload (`assetPayload`, a plain value carrying either `data` or a `path`, since it crosses the singleflight boundary and must own no descriptor) is re-opened and streamed by `AtomicPut` as an `*os.File`, i.e. an `io.ReadSeeker` the S3 signer and its retries can rewind. Peak heap used to be `SRR_ASSET_WORKERS × (source + payload)`; a video-heavy feed spiked hundreds of MB of transient heap on an 8 GB host. The two reads of a big source see the same bytes because a cache file is written once, before anything references it, and never rewritten in place. Built once per `fetch` run in `cmd_fetch.go` from `db.Backend`, shared across workers (concurrent-safe). The external-ingest upload step (`fetchRun.uploadAssets` → `rewriteItemAssets`, run from `Feed.fetchURL`; see Ingest §) calls it once per `#`-marker against the run's shared cache dir (`fetchRun.cacheDir` = `assetCacheRoot()`).
- **Per-asset pre-upload processing (`SRR_ASSET_PROCESS` / `globals.AssetProcess`):** an optional operator-configured command (e.g. `webify -m 720`) run on **every** asset just before upload — image/video transcoding being the motivating case (covers external-ingest and internal-mod markers uniformly, since both funnel through this one step). Runs **only on a store miss**: the existence check keys on the **source** hash *before* processing, so an already-uploaded asset is never re-processed. `runProcess` substitutes the cache file path for each `{input}` token (per arg), or appends it as the final arg. With an `{output}` token the command runs in **file mode**: SRR substitutes a fresh staging path under `<cache-dir>/_processed/` (`assetFetcher.procDir`; OS temp fallback when unset — big transcodes must not land in a tmpfs `/tmp`, and a crash-leaked output inside the cache tree ages out via the sweep; success removes it immediately), the command writes its bytes there and prints a `{mimetype,extension,encoding}` JSON to stdout — mimetype/encoding ride the upload as `store.ObjectMeta`, the extension is for the peek-decided key. The staging file **is** the upload payload (streamed by `AtomicPut`, never slurped), removed by `resolveAndUpload` once the upload has read it. Without `{output}`, processed bytes come from stdout (in memory, no declared metadata — with no asset-peek either, Content-Type comes from sniffing). stderr is **captured, not passed through** (asset commands narrate progress on stderr and parallel jobs would garble srr's status line): `mod.RunCommandTimeout` buffers the last 4 KiB (`tailBuffer`) and on failure folds the trailing lines (CRs count as line breaks) into the returned error; on success it is discarded — deliberately unlike `RunSubprocess`, where external ingest/mod commands keep passthrough stderr as their documented log channel. **Fail-soft** — non-zero exit, empty output, or (file mode) invalid metadata JSON uploads the original unchanged. Bounded by its **own** timeout `--asset-process-timeout` / `SRR_ASSET_PROCESS_TIMEOUT` (default **0 = unlimited** — media transcoding can run long; bounded only by run cancellation), separate from `--cmd-timeout`, which governs ingest/mod commands and **never** affects asset work (both `runProcess` and `runPeek` go through `mod.RunCommandTimeout(ctx, procTimeout, …)`; ≤ 0 adds no deadline). The dedup key always hashes the **source** bytes, but its **extension** comes from `asset-peek` when configured (else the source extension); the **output** keeps a fail-soft size guard in both modes (`checkProcOutput` for file mode — one open+`Stat` that also proves the upload's open will succeed; an inline `len(out)` check for stdout mode): an over-`SRR_MAX_ASSET_SIZE` output uploads the original instead — that output is generated here and isn't download-bounded. Empty `SRR_ASSET_PROCESS` disables (pure pass-through). Asset jobs run concurrently across a feed's items, bounded globally by `SRR_ASSET_WORKERS` (the `a.sem` pool, held by the leader only). A marker referenced by several items (same feed or across feeds — the run's `assetFetcher` is shared) is coalesced by `assetFetcher.flight` (a `singleflight.Group` keyed on the source content hash) via `DoChan`, so one wave peeks/transcodes/uploads exactly once and the rest receive the leader's key without taking a slot — a waiter whose own feed cancels bails on its caller ctx. The body runs under the run/shutdown ctx (`a.baseCtx`), not the leader feed's, so the result is shared with the wave (a shared asset that genuinely fails to upload fails every referencing feed — none can publish content pointing at a missing asset; each self-heals next fetch) WITHOUT one feed's cancellation poisoning a healthy follower. The `seen` memo still short-circuits the cheaper sequential/cross-call hit before `flight`; the store-existence check stays the cross-run backstop. The matching out-of-repo converter is `webify` (`~/ws/webify`, on PATH as `~/.local/bin/webify`): auto-detects image→WebP / video→WebM, `webify <input>` writes to stdout.
- **Per-asset identification (`SRR_ASSET_PEEK` / `globals.AssetPeek`, the `assetFetcher.peek` field set in `cmd_fetch.go`):** an optional probe run on **every** asset **before** the dedup check (so it runs even for already-uploaded assets — the accepted cost). `runPeek` substitutes/append the cache path like `runProcess` and parses a `{mimetype,extension,supported,encoding}` JSON from stdout. The **extension** becomes the stored object's key extension (`contentHashKey(peek.extension, sha256(source))` — so a transcoded `.gif`→WebP rides a `.webp` key while dedup still keys on the source bytes); the **mimetype/encoding** become the object's `store.ObjectMeta`; **supported=false** hosts the original bytes and **skips** `asset-process` (peek reports the real source type for an unsupported asset). Precedence: in `{output}` mode `asset-process`'s declared mimetype/encoding (the actual result) override peek's; a `process.extension` disagreeing with the peek key only **warns** (the key is already chosen). **Fail-soft**: a peek error / invalid JSON falls back to the source extension and `supported=true`. Empty disables (the object then gets the source extension + `application/octet-stream` default). **Corrupt-media guard**: a peek that runs fine but identifies NOTHING (`supported=false`, empty/`octet-stream` mimetype, empty extension) on a source whose extension claims media (`isMediaExt`) classifies the file as broken bytes — `UploadCacheRef` returns the `errCorruptAsset` sentinel, `rewriteItemAssets` declines the marker with a WARN (the article publishes without working media; the reader collapses the dead element) instead of hosting garbage (the chron-437 bug) or failing the feed (the bytes won't improve on retry — a hard error would wedge it). Identified-but-unsupported formats and non-media extensions keep the host-as-is contract. **Cycle-level degradation warning**: per-run `assetFetcher.procFailed`/`corrupt` counters (bumped on each peek/process command failure and each corrupt decline) are surfaced by `runFetch` as one WARN per cycle — a systemic cause (webify missing from the service PATH) otherwise drowns in per-asset noise while every asset silently ships unprocessed with `octet-stream`.
- `RewriteAttrs(content, fn)` (`mod/helper_assets.go`): the generic HTML attribute walk over `assetAttrs` (img/video/audio `src`, video `poster`, **plus `a href`**, the generic-file set) behind the upload step. The caller's `fn` returns `(newVal, ok, err)` and owns the `#`-marker upload policy — which values are markers, how files are stored, and which failures are fatal (a non-nil `err` aborts the walk and fails the feed) — keeping that policy out of `mod`.
- Idempotency: download dedup is the ingest strategy's (its cache check); upload dedup is SRR's — `UploadCacheRef` skips the `Put` (and the `SRR_ASSET_PROCESS` run) when the source-hash key is already in the store (one `Backend.Stat` probe — its nil error proves presence), so a re-run re-uploads and re-processes nothing.
- `assets/` is a reserved store prefix in the writer↔reader contract (analogous to `idx/`/`data/`); the frontend (`fmt.ts`) resolves it against the pack base. The store's `AtomicPut` carries a `store.ObjectMeta{ContentType, ContentEncoding}`: `S3` stamps it (with meta unset, Content-Type falls to `contentTypeForKey` — SRR's own gzip objects, db.gz + seen slots + pack-grammar names, declare `application/gzip`; anything else gets `application/octet-stream`); local/SFTP ignore it and rely on the static server's mime-by-extension at request time. So a peek-corrected key **extension** is what fixes local/SFTP rendering, while the explicit mimetype hardens S3. **An asset's type is never derived from its key extension, and the store layer never sniffs.** peek/process is its single source of truth wherever either is configured — including when a peek fails soft and declares nothing. The one exception is the zero-config case, **no asset-peek command at all AND nothing declared**: `resolveAndUpload` then sniffs the payload's own first 512 bytes (`http.DetectContentType`) and adopts the answer only when it is an INERT type — `image/*`, `video/*`, `audio/*`, `application/ogg`, `application/pdf` (`sniffedMediaType`). Otherwise every self-hosted image on a zero-config install is served as an `octet-stream` download. The allowlist is the security half: `assets/` is a separate origin a reader loads media from, so a sniffed `text/html` would turn an attacker-influenced `a href` marker into script execution on the store's own domain (and `*.llera.eu`'s Access cookies are SameSite-adjacent to it), where an octet-stream download is inert.
- `GUID` and `Published` are immutable for all modules (built-in or external; change = error). Enforced in `processItem` after each pipeline step — the captured value before the step is compared to the post-step value, attributing changes to the offending module.
- `RawItem.Raw` is set by the ingest parser (`ingest/feed.go`) to the parsed entry as `mod.RawFeedItem` (`map[string][]mod.RawField`); modules can type-assert it for typed access. External (shell) modules see the same data as JSON via the short keys `@`/`$`/`+` (text/attrs/children).
- `RawItem.Drop bool` (`json:"drop,omitempty"`) — set to `true` by a pipeline step (built-in or external) to signal that the item should be discarded. `processItem` short-circuits on the first `Drop=true`: returns nil, skips remaining steps and post-loop normalization. Callers (`feed.go` `fetchURL`, `cmd_preview.go`) check `i.Drop` after `processItem` returns nil and `continue` to skip storing/rendering the item. The GUID is already in the boundary map by the time the second-pass loop runs, so a dropped item stays deduped on the next fetch without any extra handling.
- `RawItem.Lang string` (`json:"lang,omitempty"`) — the article's ISO 639-1 language code, **persisted to the data packs** (since 2026-07-19; see the `ArticleData` bullet): stamped by the **always-on PRE-pipeline detection** in `processItem` (`mod.DetectLang` in `mod/helper_lang.go`: whatlanggo trigram detection over title + HTML-stripped content — `extractText` in `helper_html.go`, **hard** 4 KiB cap on the extracted TEXT, a single whitespace-free token truncated on a rune boundary rather than written whole, which is what bounds no-space scripts like Japanese; the *document* is deliberately parsed in full — a byte cut on markup is not a cut on text, and truncating let text-sparse markup either empty the extract or leave only a short foreign boilerplate line that classifies confidently, which `keep_lang` would then drop for good; fail-open gate ≥ 24 runes at ≥ 0.8 confidence, else Lang stays empty; an ingest-declared value is never clobbered), so every pipe step sees it — `#filter keep_lang` decides from it, and a shell mod can read/override it on the external wire. Detection's gate is deliberately conservative, so the short microblog-style items `keep_lang` most needs a value for routinely go unstamped: the **feed's own declared language** (`ingest.Result.Lang`) is the last resort under them, folded and validated by `mod.NormalizeLangCode` (exported for exactly this — `normalizeLang` + `validLangCode`, answering `""` for a tag detection could never produce, so a junk `<language>` stamps nothing). Full precedence: ingest-declared per-item > confident detection > feed-declared. A post-pipe re-attempt runs only when the pre-pipe pass produced nothing of its own (empty, or still exactly that feed-declared fallback) AND `DetectLang`'s inputs changed, and it overwrites only on a real code. `langCode` is the one Lang→639-1 mapping — whatlanggo's table corrected by `iso6391Extra` for Western Persian (`fa`) and Eastern Yiddish (`yi`), which it maps to `""` despite those languages having 639-1 codes; without the correction `keep_lang=fa` was an "unknown code" that failed `Validate` and took the whole feed down. Carried `RawItem` → `Item` → `ArticleData.Lang` (`json:"g,omitempty"` since 2026-07-19) into the data packs, so the wire type `IArticleWire` carries `g?: string` (`gen-ts`); read-side `parseDataPack` round-trips it, and absent means "unknown" (uncertain detection, or a pre-field article). Mutable, unlike GUID/Published.

## Ingest (`ingest/`)


An "ingest strategy" is the I/O+parse layer that produces `mod.RawItem`s from a URL. The default zero-config behaviour is the historical RSS/Atom/RDF path (`#feed`); alternative strategies — shipped out-of-repo as external shell commands — cover URLs that aren't feeds. Selection per feed: `ingest.Select(feed.Ingest, recipe.Ingest, default.Ingest)` (variadic, first non-empty wins) — the feed-level override, falling back to the feed's resolved recipe's ingest, falling back to the `default` recipe's ingest, falling back to `#feed`. Empty strings fall through; persistence uses `omitempty`.

Built-in names start with `#` and resolve through the package's `Register` registry (init-time). Anything not starting with `#` is treated as a shell command per the external-ingest protocol. Only `#feed` ships built-in; source-specific strategies live out-of-repo as external commands.

Mirrors `mod/`'s architecture: a `Fetcher` struct (built by `New()`) holds the registered built-in `FetchFunc`s in a name→func map; `Fetcher.Fetch(ctx, args, ...)` dispatches by name — built-ins for matching keys, shell-command fallthrough for anything else.

- **`main.go`** — `Request` / `Result` structs, `FetchFunc` type (`func(ctx, *http.Client, buf, Request) (Result, error)`), direct registration `Register(name, FetchFunc)` (built-ins are stateless, so `New()` shares the registry rather than instantiating one per call), `Select(feed, global) string` precedence helper (final `#feed` fallback, exported as the `Builtin` const — the token callers compare against to gate subscribe-time discovery), the `Fetcher` struct + `New() *Fetcher`, and `Fetcher.Fetch(ctx, args, client, buf, req)` which routes `args` to a built-in if registered or executes it as a shell command otherwise. `ProbeBuf(maxSize)` lends a pooled read buffer to the one-off PROBE paths (`Resolve`, `previewFetch`), which have no per-worker buffer of their own; it re-slices a reused buffer to the caller's limit, which is why `readBody` reports `len(buf)-1` rather than `cap(buf)-1` as the size that fired. External wire schema is the JSON encoding of `Request` (stdin) and `Result` (stdout) — see struct tags; stderr is passthrough. `Result.Lang` (`lang`, omitempty) is the feed's OWN declared language, set by `#feed` from the parsed document and settable by an external strategy: the LOWEST-priority language source, consumed only by `processItem`'s stamp (a per-item `RawItem.Lang` and a confident detection both beat it) and deliberately unvalidated here — `mod.NormalizeLangCode` is the gate. A non-zero exit code or empty stdout is a hard error (fails just that feed's fetch); stdout is capped at 64 MiB. Items on the wire are `mod.RawItem` records, so external strategies emit `guid` as the FNV-32a hash (uint32) of any stable per-item string, matching the dedup contract used by built-ins. `published` is RFC3339 (null/absent for dateless). The author-facing protocol spec + a reference implementation live in `backend/README.md` (Ingest Strategies); the protocol tests are in `ingest/external_test.go`.

**External file self-hosting.** The ingest engine owns no asset machinery: it just sets the external command's working directory to `Request.AssetDir` (`cmd.Dir`) so the command stashes/references files with relative paths. The caller (`main`) owns the rest. `FetchCmd.fetch` creates **one cache dir shared by every feed this run** = `globals.CacheDir` (`MkdirAll`, kept across runs; **always set** — the kong `${cacheDir}` default covers unset, main()'s post-parse floor covers an explicitly empty `cache-dir:`, both resolving `defaultCacheDir()` = `os.UserCacheDir()/srr`), stores it on `fetchRun.cacheDir` (creation is mandatory — a command handed an empty working dir would run in SRR's cwd), and `Feed.fetchURL` hands it to **every** feed as both `Request.AssetDir` and the upload-step `cacheDir` — no strategy gate, so a built-in fetcher may download into it too. The upload itself is the **automatic end-of-pipeline step** `fetchRun.uploadAssets` (run from `Feed.fetchURL` after `processItem`, which stays a pure, store-free transform; marker-bearing items fan out concurrently, bounded by the `assetFetcher`'s run-global `SRR_ASSET_WORKERS` pool): for each item it calls `mod.RewriteAttrs(content, fn)`, and `fn` scans for **`#`-markers** — a value starting with `#` whose remainder names an existing regular file in `cacheDir` (e.g. `#/photo.jpg`) — uploading each through `assetFetcher.UploadCacheRef` (content-hash key, upload-if-absent) and rewriting the marker to the returned key. `UploadCacheRef` classifies its guard failures with the `errNotAsset` sentinel — references naming no regular file (an ordinary `#fragment` anchor) or resolving outside the cache dir (attacker-influenced content) are **declined** by `fn` (marker untouched; the one containment implementation lives in `UploadCacheRef` alone); any other upload failure returns the error, which `RewriteAttrs` surfaces so `Feed.fetchURL` **hard-fails the whole feed** — feed state (watermark/dedup/etag) untouched, so a transient failure self-heals next fetch. (Oversize is not one of these: `--max-asset-size` is enforced **at download** by `#selfhost`/ingest, so an over-cap asset is dropped there — keeping its remote URL — and never reaches the upload step.) `<video poster>` is **not** a usable target *for ingest-injected markers*: `#sanitize`'s poster regex (`^(https?://|assets/)`) strips a `#`-poster before the upload step runs (ingest markers ride the pipeline from the start); the built-in `#selfhost`, by contrast, runs *after* `#sanitize` (placed after `#default`) and **does** self-host posters — its markers are created post-sanitize and never re-sanitized. Download dedup is the command's (cache check); upload dedup is SRR's (content hash + store existence check). The cache is **self-maintaining**: after each cycle's Commit, `sweepAssetCache` (cmd_fetch.go) deletes files unused for longer than `--cache-max-age`/`SRR_CACHE_MAX_AGE` (default 72h; 0 disables). Relevance = **mtime**: `UploadCacheRef` touches every source file it consumes (before the memo/store-hit/upload branching, so all paths count) and the cache consumers touch on reuse (`srr-telegram`'s size-validated cache check, `#selfhost`'s URL cache), so any file a live feed still references stays fresh — including a big backlog warming up across failing cycles — while orphans age out. A `FetchFunc` owns only I/O and parsing — dedup, watermarking, pipeline modules and storage stay in `Feed.fetchURL`/`processItem`. Built-in `FetchFunc`s and the shell path must be concurrent-safe (one `*Fetcher` shared across workers; unlike `*mod.Module` it isn't pooled).
- **`feed.go`** — Built-in `#feed` strategy (registered inline in `init`): the zero-config default. HTTP GET with `If-None-Match` / `If-Modified-Since` hints into the shared per-worker buffer, then `ParseFeed`. Returns `NotModified` on 304; populates `ETag` / `LastModified` for the next request. **Feed auto-discovery**: when `ParseFeed` reports `errNotFeed` (the document is not a recognized feed — an HTML page, unknown XML root, or non-XML — *as opposed to* a genuine fault parsing a real feed) and the response looks like HTML (`text/html` Content-Type or body starting with `<!doctype html`/`<html`), `discoverFeedLink` (`feed_discover.go`) scans for `<link rel="alternate" type="application/rss+xml|atom+xml|…">` in the HTML head, fetches the discovered URL, and sets `Result.ResolvedURL`; `feed.go` persists `ch.URL = ResolvedURL` without resetting dedup/etag/vitals. One-hop guard: a discovered page that is also HTML-without-feed returns the original error and does not recurse. **`errNotFeed`** is the unexported sentinel that classifies "not a feed" so the discovery branch (here, fetch-time) never fires on a broken-but-real feed. **`Resolve(ctx, client, rawURL, maxSize)`** is the subscribe-time wrapper: it runs the same `feedFetch` discovery once and returns the canonical feed URL (rawURL if it already serves a feed, the discovered target if it's an advertising HTML page, or an error if neither) — used by `feed add`/`upd -u`/`import` (see `cmd_feeds.go`/`cmd_import.go`). Also houses the streaming RSS/Atom/RDF parser: `ParseFeed(data, fn) (title, lang, partial, err)` (returns the feed's own channel/feed-level title — parent-checked so an `<item>`/`<image>` title never masquerades as it; surfaced as `Result.Title`, consumed by serve's `GET /api/resolve` — plus `lang`, the feed's own declared language from the root's `xml:lang` (Atom's spelling, also legal on `<rss>`/`<rdf:RDF>`) else a `<language>`/`<dc:language>` directly under `<channel>` (RSS 2.0 / RDF), first non-empty winning and returned verbatim under the same parent check, surfaced as `Result.Lang` — plus `partial`, true — and NOT an error — when the parse stopped at a malformed mid-feed element, so the items streamed so far are a good prefix of an incomplete response, which is why the caller withholds the ETag/Last-Modified validators (`Result.Partial`); a non-feed document is reported wrapped in `errNotFeed`; a fault parsing a recognized feed is a plain error) and the package-private `hash(string)` used for GUID stability (the FNV-32a contract external fetchers replicate).
- **`feed_discover.go`** — `discoverFeedLink(htmlData, baseURL)`: scans HTML for the first `<link rel="alternate">` with a recognised feed MIME type using `golang.org/x/net/html.NewTokenizer`; returns the href resolved against baseURL. Case-insensitive rel (including multi-valued), tolerant of malformed/partial HTML.
