# CLAUDE.md

## Project

**SRR Backend** — Static RSS Reader Backend. Go CLI that fetches RSS/Atom/RDF feeds into gzip-compressed pack series (idx/, data/). Backends: local filesystem, S3, SFTP, HTTP.

## Commands

The root `Makefile` is the unified entry point for both halves of the monorepo; prefer it over raw `go` commands:

- `make build-be` — build the binary to `dist/srr`
- `make test-be` — `go test ./...`
- `make vet-be` — `go vet ./...`
- `make format-be` / `make format-check-be` — `gofmt -w .` / gofmt gate (the latter runs inside `make verify-be`)
- `make lint-be` — `golangci-lint run ./...` (gate-clean; runs inside `verify-be` — config in `.golangci.yml`: std-error-handling preset, errcheck + SA5011 off in tests)
- `make generate` / `make generate-check` — regenerate / freshness-check `frontend/src/js/format.gen.ts` (`srr gen-ts`)
- `make verify-be` — vet + gofmt check + lint + build + test + generate-check
- `make fuzz-be` — smoke every fuzz target (`FUZZTIME` per target, default 20s). Kept OUT of `verify`: the checked-in seed corpora already run on every push as ordinary unit tests (`go test` executes each `f.Add` seed), so a broken target is caught there; this is for finding the inputs nobody thought of. `.github/workflows/fuzz.yml` runs the same targets nightly at 5m each and uploads any crasher it writes to `testdata/fuzz/`. Targets: `FuzzParseIdxPack` + `FuzzIdxWriteParse` + `FuzzParseSeen` (the byte-level store parsers, `fuzz_test.go`), `FuzzParseFeed` (`ingest/` — hostile network bytes every five minutes), `FuzzSanitize` (`mod/` — asserts the XSS boundary over a PARSED DOM, not a regexp on the string: sanitized output is mostly text, and text may legally contain " onerror=")
- `make release VERSION=…` — cross-compile all platforms (`CGO_ENABLED=0 -ldflags "-s -w"`)

Direct equivalents when working inside `backend/`: `go build -o srr .` (the Makefile artifact is `dist/srr`), `go test ./...`, `go test -run TestName .`, `go test -v ./store/`.

## Architecture

> **Deep-dives live in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).** The per-module (`mod/`) and per-strategy (`ingest/`) catalogs were moved there verbatim and are linked from their sections below. `Store (store/)` and `Pack Storage` stayed here on purpose — their contracts bind most backend edits, not just edits to themselves.

- **`main.go`** — CLI via `alecthomas/kong` + YAML config. Source: `$SRR_CONFIG_INLINE` (raw YAML, takes precedence) → `$SRR_CONFIG` (file path) → `$XDG_CONFIG_HOME/srr/srr.yaml`. (Remote URL config sources and a `srr config <key> <value>` updater were built then deliberately reverted 2026-07-04 — `SRR_CONFIG` is a local path and `srr config` is read-only.) **Flags (CLI simplification, 2026-07-26)**: `Globals` shrank 24 → 5 — `-o/--store` (also accepts a name from srr.yaml's optional top-level `stores:` alias map: exact match substitutes the mapped path/URL, anything else stays the literal, so `srr -o local` works next to `-o packs`), `--force`, `-d/--debug`, `-w/--workers`, hidden `--cdn-url`. The ~18 cycle knobs moved to three shared kong-embedded structs in `flags.go`: `cycleFlags` (pack-size, max-deltas, max-delta-bytes, max-batch-bytes, max-asset-size, asset-process, asset-peek, asset-workers, asset-process-timeout, cache-dir, cache-max-age, fetch-backoff-max, notify, notify-after) embedded in `fetch`/`serve`/`mcp`/`config`; `gcFlags` (keep-manifests) additionally in `store compact`; `netFlags` (max-feed-size `-m`, cmd-timeout, allow-private-fetch) additionally in `preview` and `feed add`/`upd`/`import`. Their `AfterApply` hooks copy the resolved values into the runtime `globals` struct — which keeps EVERY field, staying the single runtime carrier `db_pack.go`/`notify.go`/the `mod` applies read — and floor them; `kong.Parse` runs `AfterApply` only for the executed command, so tests that set `globals` directly are unaffected. `main()` seeds the moved fields (compiled default, overridden by its `SRR_*` env var) via `seedScopedDefaults` BEFORE Parse, so a non-embedding command that still reaches the writer (`feed rm` draining a live delta chain) never runs on Go zero values — yaml deliberately does not reach those seeds. Every `SRR_*` env name is unchanged, and the moved flags keep resolving from their existing TOP-LEVEL srr.yaml keys via the wrapped resolver (`configResolver`, allowlisted by `scopedFlagNamesList` in `flags.go` — scoped to exactly those flags, so a stray top-level key can never be captured by a per-command flag). Command tree: `fetch`; `art` (alias `a`); `feed` (`f`): `add`, `upd`, `rm`, `ls`, `show`, `edit`, `apply`, `import`, `export`; `store`: `export`, `import`, `dedup`, `compact` (`feed import`/`export` remain the OPML pair, unambiguous now that the store-config pair is namespaced); `asset`: `heal` (`cmd_asset.go` — overwrite an existing `assets/` object's bytes in place, the operator repair path for a published-broken asset: key grammar via `assetKeyRe` (renamed from `healKeyRe` — now also the validation gate for expiration's asset harvesting, see `db_expire.go`), must already exist unless `--create` (re-create a referenced-but-deleted object), Content-Type from `--content-type` or the key extension; a deliberate hash≠bytes break since immutable articles reference the key forever); `recipe`; `syndicate`; `watch` (`ls`/`show`/`set`/`rm`, `cmd_watch.go`); `preview` (`p`); `config` (`c`); `inspect` (`i`); `frontend` (`fe`): `update`; `version`; `serve`; `mcp` (`cmd_mcp.go`); hidden `gen-ts`. The optional top-level `secrets:` YAML section is **scoped** — `secrets → <scope> → <NAME> → <value>` — parsed by `parseSecrets` (`secrets.go`) and pushed via `mod.SetSecrets`; `mod.SubprocessEnv(ctx)` merges into an external ingest/mod command's environment only the scopes the feed's resolved grant names (the `secrets` axis: feed > recipe > default, `resolveSecrets` in `feed.go`, stamped onto the fetch ctx via `mod.WithSecretScopes` — no grant ⇒ no secrets, fail-closed; SEC5). Granted secrets win over the ambient env; NOT applied to asset-process/asset-peek; the operator-global `--notify` hook alone gets every scope (`mod.AllScopes`). Hard errors: an empty scope name or one containing `.` (the `srr config` lookup separator), an empty var name or one containing `=`, and a pre-scope FLAT map (rejected with a migration hint); values stay plaintext in `srr.yaml`. A granted scope srr.yaml does not define warns at fetch time (`mod.MissingScopes`) and contributes nothing.
- **`cmd_inspect.go` / `cmd_inspect_check.go` / `cmd_inspect_report.go`** — `InspectCmd` (`srr inspect`): pack consistency checker. Split across three files by responsibility: command entry + fetchers (`cmd_inspect.go`: `openFetcher`/`httpFetcher`/`loadCore`/`loadDataPack`), validation checks invoked by `--validate` (`cmd_inspect_check.go`), single-mode reports for `--chron`/`--filter`/`--list-tags`/`--from-hash` (`cmd_inspect_report.go`). The idx parse + addressing mirror itself lives in `idx_read.go` (shared with `srr art`). Modes: `--chron N` (single-entry inspection: feed_id + resolved data packId/offset + the stored fetched_at), `--validate` (full sweep: bounds-vs-data, db-meta cross-check, feedCounts continuity across pack boundaries, unknown feed_ids, latest-pack file presence, idx header-summary coverage/content vs `hdrs`, meta coverage/consistency via `checkMeta` — overclaim, latest tail count vs `mt`, shard sizes, every title's grams probe positive in its shard bloom, summary == concat of shard headers; db-meta expiration checks: `0 ≤ add_idx ≤ total_articles` and `0 ≤ xp ≤ total_art` range checks plus a live-count cross-check — live idx entries at `chron ≥ add_idx` must equal `total_art − xp` (`feedIDStats`; reuse-proof, since a reused id's legacy entries sit below `add_idx`) — replacing the pre-expiration "first idx occurrence < add_idx" issue, which is now expected behavior; the all-time `total_art == idx count` check stays, a known id-reuse limitation, commented in place; manifest consistency — root↔manifest agreement, name-table density/uniqueness (M3/M5), every listed name exists (M4), generation density M2, and the asset reference sidecar's body (it parses, and its coverage start is inside the store — an unreadable one silently downgrades retention to "keep everything I cannot prove dead") (`checkManifest`, `cmd_inspect_manifest.go`); and chron-permanence — invariant M8, no chron renumbered across the last K manifests: `total_art`/`next_pid` and every same-URL feed's `total_art`/`add_idx`/`xp` only ever grow (`checkChronPermanence`, the gate on `srr store compact`)), `--filter <tag|feed_id>` (filter resolution + count, mirrors frontend filter math — sums live counts, `TotalArt − Expired`), `--from-hash '<hash>'` (replays `nav.fromHash` end-to-end), `--list-tags` (mirrors `groupFeedsByTag`; per-tag article totals are live counts too). `--url` for HTTP CDN; otherwise uses `--store`. Diagnoses the `(reading 'f')` crash class in frontend `nav.ts` (`showFeed` accesses `data.db.feeds[article.f]`).
- **`cmd_fetch.go`** — `signal.NotifyContext` for graceful shutdown. **The cycle is TWO store scopes (FET5, 2026-07-26)**: `runFetch` = a read-only `fetchPhase` — snapshot the feed set/recipes/dedup pool (plus per-feed `fetchedFeed` guard records: pre-fan-out URL, `fetchState`, AssetBytes baseline), then the whole network fan-out with NO store lock (a `--spool` producer ends here) — and a short LOCKED `commitPhase` that re-loads the store fresh, re-stamps `core.FetchedAt` (articles must stay chron-monotone past any peer commit between the phases), folds the results back per feed (`applyFetched` — the local sibling of `applyInbox`: discards a record when the feed is gone, its URL was repointed, or ANOTHER fetch advanced its state underneath (the GUI-race duplicate guard); an applied record adopts state wholesale incl. its own discovery repoint, merges dedup stamps, repoints items at the live feed — though the **AssetBytes delta is charged ABOVE those two guards** for any record with a live feed: the fan-out's `assets/` Puts are durable whether or not the articles land, and a later cycle re-referencing them takes `UploadCacheRef`'s 0-byte store-existence branch, so charging only on apply made every discarded upload a permanent under-count driving `ab` toward 0; the removed-feed discard stays uncharged by construction), then runs the unchanged PutArticles→Commit chain. Lock hold drops from minutes to seconds, so operator mutations no longer 409 against a running cycle, and the `.locked` lease (REL3) is stamped far inside its TTL. `checkStoreBusy` is the fetch phase's advisory fail-fast probe: a LIVE foreign lease is refused before the fan-out with the same `os.ErrExist` contract (absent/own/expired/legacy fall through to the write phase's real acquire, the single authority). `errgroup` (`golang.org/x/sync/errgroup`) with `SetLimit(globals.Workers)` and, from `FetchCmd.workerPools()`, the fan-out's reusable worker state (`fetchPools`: a `sync.Pool` of feed buffers, a `sync.Pool` of `*mod.Module` processors, the shared `*ingest.Fetcher`). Per **command**, built on first use and reused by every cycle (FET14, 2026-07-26 — an `--interval` loop used to rebuild them every five minutes, recompiling bluemonday policies for nothing; `sync.Pool`s so an idle loop returns the memory at GC). Cycles are serial within one `FetchCmd` (serve and MCP each construct their own), so the lazy build needs no lock. The fan-out is additionally gated per hostname by `hostGate` (`perHostConns` = 2): feed sets cluster on a few hosts, and `--workers` simultaneous connections to one origin at a fixed interval is the burst shape datacenter-IP WAFs score as a bot. It bounds request *initiation*; the transport's `MaxConnsPerHost` only pools the resulting connections. Scope is the feed-level fetch only — the per-item second pass (`#readability`/`#selfhost`) targets article hosts and is ungated; a URL with no parseable host is not gated. Articles sorted by published time ascending before storage. Order: `PutArticles` → `SyncIdxSummary` → `SyncMeta` → `SyncWatch` → `ExpireArticles` → `SyncOutFeeds` → `SyncSeen` → `SyncRefs` → `GC` → `Commit` → post-flip reclamation (`SyncRefs` after expiration so one object carries both additions and releases, fatal like `SyncSeen`; `SyncWatch` beside `SyncMeta` — both chron projections over the same `written` slice, warn-only for the same reason; expiration before the out-feed sync so the same cycle's syndication excludes what just expired, and warn-only like the sync steps; all run on every cycle incl. serve's loop and the GUI `only`-mode — global maintenance, production `now` = `db.core.FetchedAt`). `GC` is ONE warn-only sweep (`docs/MANIFEST-SPEC.md` §7) run BEFORE the Commit, so its `gcm` advance rides this cycle's own root flip. Then the ingest-cache age sweep (`sweepAssetCache`, `--cache-max-age`/`SRR_CACHE_MAX_AGE` default 72h, 0 disables; post-Commit only — see "External file self-hosting" for the mtime contract). `--interval` / `SRR_FETCH_INTERVAL` runs fetch in a loop; the body is `FetchCmd.fetchLoop(ctx, client)` (single cycle when ≤ 0, else cycle→sleep→repeat until ctx cancel, returning nil on clean shutdown and logging — not propagating — a failed cycle), shared with `srr serve --interval`. **Feed-subset filter** (`feedFilter`, embedded in both `FetchCmd` and `ServeCmd`): `--tag`/`-g`, `--feed`/`-i`, `--exclude-tag`, `--exclude-feed` — all `sep:","` or repeated, env `SRR_FETCH_TAG`/`_FEED`/`_EXCLUDE_TAG`/`_EXCLUDE_FEED` (empty env is a no-op), so the same restriction reaches the persistent `srr serve --interval` loop (serve copies its `feedFilter` into the constructed `FetchCmd`). `FetchCmd.selectFeeds(db)`: the GUI single-feed `only` path is unchanged (exact ids, hard error on unknown); otherwise `feedFilter.apply` builds the include set = union of tag matches (`matchTag`: **hierarchical** — exact or under the `sel/` subtree, so `news` matches `news/tech` but not `news2`) and feed-id matches — or every feed when no include selector — minus the exclude matches (sorted by id) — and finally, on the unattended loop path only, the **dormancy backoff** thins the result (`backoffActive`/`targetInterval`/`filterDue`): each feed's poll interval drifts up as `(now − last_new)/8` from the loop `--interval` base (first skip after ~8× base of quiet), capped at `--fetch-backoff-max`/`SRR_FETCH_BACKOFF_MAX` (default 1h; 0 = kill switch, poll everything every cycle), keyed on `LastOK` as the poll clock (`now` = `db.core.FetchedAt`). A feed that produces snaps back to base next cycle. A **failing** feed (`FailStreak > 0`) takes a separate path (`retryInterval`): `LastOK` freezes while failing, so the retry clock is the in-memory `FetchCmd.lastAttempt` map (stamped for every selected feed; process-local, so a restart grants one full poll), cadence `base << min(FailStreak, 10)` capped at the same max, never below base. Backoff only delays retries — `ferr`/`fail_streak` keep reporting, and the first success resets the streak. One-shot runs, the GUI `only` path, and explicit include selectors always poll at full rate. Warn-only, never abort: a selector matching nothing and an empty final set each log one `slog.Warn`; a zero-feed cycle still runs global maintenance. Error summary logged at end. The end-of-pipeline asset upload is parallel too: `Feed.fetchURL` defers to `fetchRun.uploadAssets`, which fans marker-bearing items over a per-feed `errgroup`. The **run-global** asset worker pool lives on the shared `assetFetcher` (`a.sem`, `SRR_ASSET_WORKERS`/`--asset-workers`, default nproc, independent of `--workers`) and is held by the singleflight **leader** job only — followers coalescing on the same bytes never pin a slot. The singleflight body runs under the **run/shutdown ctx** (`a.baseCtx`), not the per-feed errgroup ctx, so one feed's cancellation can't poison a follower feed sharing an asset. Marker-less items (`mod.HasAssetMarkers` false) skip the fan-out; `FetchCmd.fetch` sizes the pool (cap ≥ 1). **Live fetch stats** (`progress.go`): when stderr is a terminal, `runFetch` renders an in-place status line — `fetching · feeds done/total · new articles N · failed N · assets N (N active)`, verb flipping to `saving` for the pack-write half — via `startFetchProgress` (200 ms ticker; feed workers bump counters where `onFeed` fires, asset job counts live on `assetFetcher.active/done`, bumped by the singleflight leader). The process-wide `status` line coordinates with logging: `main` routes the slog handler through it (`log.SetOutput(status)`), so a log record erases the line, prints, redraws beneath — plain `\r` + padding, no ANSI. On a non-terminal stderr everything is a no-op/passthrough, so logs stay byte-clean.
- **`cmd_feeds.go`** — One feed = one URL. `AddCmd` (`srr feed add`, strict-create; flags `-t/--title`, `-u/--url` (single, required), `-g/--tag`, `-r/--recipe`, `-i/--ingest` + repeatable `-p/--pipe` + repeatable `--secrets` (feed-level {ingest, pipe, secrets} overrides on top of the recipe), `-e/--expire-days N` (0 = keep forever)), `UpdCmd` (`srr feed upd ID` — same fields; `-i ""` clears the ingest override, a lone `-p ""` the pipe, a lone `--secrets ""` the grant; `-u/--url` repoints the source), `RmCmd`, `LsCmd` (filter by `-g/--tag`, yaml/json), `ShowCmd`, `ApplyCmd` (`srr feed apply` reads feed JSON from `--file PATH` or stdin; single object or array; whole-input atomic; create when `id` absent, full-replace update when present, error on a missing referenced feed), `EditCmd` (`srr feed edit ID` opens `$VISUAL`/`$EDITOR`/`vi` on the feed JSON; no-change is a no-op; id changes refused; tempfile preserved on parse or apply error). The per-feed fetch state (`ETag`/`LastModified`/`Watermark`/`BoundaryGUIDs`/`FetchError` + the `LastOK`/`FailStreak`/`LastNew` vitals) is preserved when the URL is unchanged across `upd -u`, `apply` updates, and `edit` (`setFeedURL` no-ops on an unchanged URL); changing the URL resets it (a new source shares no dedup/cache history). `feedView` is the flat JSON/YAML shape `{id?, title, url, error?, tag?, recipe?, ingest?, pipe?, secrets?, no_title?, expire_days?, expired?}` — `error` and `expired` are read-only server-owned, reported but never applied back. Empty-string convention on `-t`/`-g`/`-r`/`-i` clears the field where allowed (title and url cannot be cleared). `normalizeFeed` validates the recipe name exists, runs the feed-level pipe through `filterPipe` + `validatePipe(…, allowDefault=true)`, the secrets grant through `filterPipe` + `validateSecretScopes`, and bounds `expire_days` to `0..36500`. **Subscribe-time discovery (automatic, networked):** `feed add` and `feed upd -u` (only when the URL actually changes) resolve the URL through `ingest.Resolve` (the `resolveFeedURL` package var — a test seam) when the feed's effective ingest is the built-in `#feed` (`resolvesFeed` gates on `ingest.Select(feedIngest, recipe.Ingest, default.Ingest)` == `ingest.Builtin`; external-ingest feeds are stored as-is). A homepage URL is repointed to its discovered feed; an unresolvable URL is a **hard error** rejecting the add/repoint. `feed apply` / `feed edit` deliberately stay offline. Every probe path (this one, `import`, `previewFetch`) shares ONE client, `resolveClient()` (a `sync.OnceValue` over `newFetchClient`, sized by `--workers`), and borrows its body buffer from `ingest.ProbeBuf` (FET14 — a client per probe never reused idle connections, and each probe allocated a fresh `--max-feed-size` buffer).
- **`cmd_art.go`** — `ArtCmd` (`srr art`): lists stored articles newest-first with cursor pagination (`-b/--before`), filter by feed ID (`-i`) or tag (`-g`), time window by `-s/--since`/`-u/--until`, with `-l/--limit` (default 50). Outputs JSON. `readAllIdx` walks the packs parsed by the shared `idx_read.go` reader (`loadIdxPacks` + `getPackRef`), filtering by `db.Feeds()`/`AddIdx`; `packReader` (one instance per run, shared by the window search and the content fill so no data pack is read twice) resolves an idx entry to its `ArticleData`, caching each JSONL data pack it parses and serving delta-region entries (`packID == deltaPackID`) from the already-parsed chain. **Time window** (`--since`/`--until`, a **half-open `[since, until)`** window — `--since` inclusive, `--until` exclusive, so consecutive windows compose without overlap; either usable alone; `since >= until` and an unparseable value are hard errors): the clock is **`fetched_at`, not `published`** — one stamp per fetch cycle applied to the whole batch makes it chron-monotone (the same property `ExpireArticles` relies on), so `packReader.findWindow` locates the window with two `sort.Search` binary searches over the entry slice, reading O(log n) data packs instead of the whole series; `published` is not monotone and would force a full scan. Consequence: a backfill's old articles ride their recent ingest time. Values parse via `parseTimeBound` — a duration before now (Go units plus the `d`/`w` extensions `dayWeekRe` rewrites to hours, so `1d12h` composes), a bare **local** date `2006-01-02`, or an RFC3339 instant; bare unix seconds are deliberately not a form, and both bounds resolve against one `now`. `Total` counts matches **inside the window**, `--before` is clamped to it (`start = min(beforeIdx, hi)`, scan floors at `lo`) so paging can't walk out. Unlike the content fill — which tolerates an entry addressing past its pack by leaving the row blank — the search treats that as a hard error: one bogus timestamp would silently relocate the whole window. `--since`/`--until` carry the `-s`/`-u` shorts: the flag scoping freed `-s` from the once-global `--pack-size`, and neither collides inside `art`.
- **`inbox.go`** — the inbox/spool pattern (`docs/INBOX-SPEC.md`), which splits fetch **egress** from the single writer so a box with better network reach can fetch feeds the lock-holder cannot (the motivating case: 16 nitter feeds dead since the loop moved to the datacenter-IP `dmz`). **Producer** = `srr fetch --spool` (+ `--spool-name`, default the hostname; `FetchCmd.spoolSlot` enforces `validSpoolName` and the deliberate-partition rule that `--tag`/`--feed` must be set): `runFetch` opens the DB with `withDBCtx(ctx, !o.Spool, …)` — **read-only, no lock** — probes its own slot for backpressure (an undrained slot skips the cycle), runs the normal fan-out, then returns early after `writeInbox` publishes `inbox/<name>.gz`; no packs, summaries, expiration or GC. **Consolidator** = the lock-holding cycle with `--inbox-producers`: `db.drainInbox` (right after the fan-out, before the batch is assembled) reads each slot, skips `cycle_id <= DBCore.Inbox[name]`, and `applyInbox` folds each record's state/stamps/items onto the authoritative feed — **discarding** records whose `url` no longer matches (the stale-config guard) or whose feed is gone; `reapInbox` removes the drained slots after `Commit`. Every per-producer failure is warn-only: a bad spool never fails the consolidator's own cycle, and its slot stays for the next retry. The envelope carries `inboxItem` fields, NOT pre-encoded pack lines — `FetchedAt` must be the consolidator's so the batch stays chron-monotone.
- **`cmd_import.go`** — OPML import with hierarchical ID selection (`-a` all, `-i` specific). Each OPML `xmlUrl` becomes one single-URL feed. OPML group hierarchy auto-resolves to hierarchical tags; `-g/--tag` overrides. Cross-folder URL dedup: a `seen` set on `importWalker` emits a URL once even when it is cross-listed in several folders (the first folder visited — case-insensitive name order — wins its tag). `-r/--recipe` stamps every imported feed. `-n/--dry-run` lists resulting feeds without importing. `applyImportDefaults` centralises post-walk Tag/Recipe stamping. (No merge mode — that was removed with the Feed concept.) **Subscribe-time discovery (automatic, networked):** the shared `resolveImportBatch` pipeline (`applyImportDefaults` → `importRecipes` → up-front `validateRecipeRef`, so a typo'd `--recipe` fails before any URL is probed → `resolveImportFeeds`) is called by both `ImportCmd.Run` and serve's `handleImport`; `resolveImportFeeds` probes every `#feed` feed concurrently (bounded by `globals.Workers`; external-ingest feeds pass through untouched) via the `resolveFeedURL` seam, repointing homepage URLs to their discovered feed. Import is **partial-success**, not atomic on resolution: resolvable feeds are imported, unresolvable ones are skipped and reported (`reportImportFailures` → the test-overridable `stdout`). `--dry-run` probes too, so its preview shows resolved URLs and the skip report. `importRecipes` reads the db.gz recipes map (read-only) to gate the `#feed` decision per each feed's resolved recipe.
- **`opml.go`** — OPML XML parsing. `ParseOPMLTree` builds `OPMLNode` tree from file; each `OPMLNode.Feed` is a single-URL `Feed`. `normalizeGroupName` converts group names to tag-safe identifiers.
- **`cmd_export.go`** — `ExportCmd` (`srr feed export`): writes the current feeds as OPML 2.0, the inverse of import — hierarchical tags become nested outline groups, one leaf outline per feed URL. `buildOPML`/`outlinesOf` are reused by serve's `handleExport` (`GET /api/export`).
- **`names.go` / `root.go` / `manifest.go` / `config_sidecar.go`** — the commit model (`docs/MANIFEST-SPEC.md`, cut over 2026-07-21). `root.go` owns `RootState` (the ~60-byte `{v, m, t}` db.gz), `parseStoreRoot`/`loadStore` (the SINGLE root resolver — `NewDB` and the read-only tools both go through it, so the writer and the checkers can never disagree about what an object is called), the `legacyCore` document of a pre-cutover store, and `migrateRoot` (the one-way cutover, run by the first LOCKED session: it COPIES the kind-lettered objects to the fresh stems the name table reserved, rewrites the dedup sidecar under one, and reaps the retired `db/` snapshots and seen ping/pong slots after the flip). `names.go` owns `ManifestNames` — the positional, run-length-encoded, OPAQUE-stem object-name table, its per-series monotone counters (`alloc`), and the `key`/`tailKey` lookups that are the only way anything in this backend learns an object's name. `manifest.go` owns the `Manifest` document, `publishManifest` (exclusive-create, so a racing writer aborts BEFORE the root flip — a poor-man's CAS on the commit), the universal crash argument stated once, and `GC` (§7's one rule: delete what the last K manifests do not name, in two shapes — `gcSweepList` lists and subtracts on a listable backend, `gcSweepDrain` is the `gcm` low-water drain when `List` reports `errors.ErrUnsupported`; either way the reachable set is ONE extra manifest read, because opaque stems make liveness a contiguous interval, and the list shape additionally uses that manifest's `names.next` as the floor below which an unnamed stem is provably dead. Its candidate set is scoped strictly to `store.ParsePackKey` + `manifest/` — never `assets/`/`out/`/`inbox/`/the roots/the frontend shell). `config_sidecar.go` owns `config.gz` and its own `.config.locked` marker.
- **`asset_refs.go`** — the asset reference sidecar (`docs/MANIFEST-SPEC.md` §4.7), the object that lets `ExpireArticles` prove an `assets/` object is dead before deleting it, so a content-hash object shared by several articles/feeds survives its FIRST expiring referrer (finding FMT2b). Both it and `outFeedsSig` operate on `managedOut()` (the non-`External` subset): external slots are never written by the cycle, their edits never un-gate managed rewrites, and an all-external store is a silent no-op even without `SRR_CDN_URL` (the zero-managed return precedes the CDN warn). Per output: feed-id set from Tags∪FeedIDs; walks a tail window (limit×10) via `walkArticles`, skipping expired articles (`chron < AddIdx`); when that window doesn't fill the limit — a **sparse** output — it falls back to `resolveOutWindow`, which resolves the window from the **idx series** instead of rescanning `data/`: it walks idx packs newest→oldest (delta region first, from the memoized chain), collects live matching chrons until `limit`, and reads ONLY the data packs holding them, with `outPackSkipper` using the `idx/h<N>.gz` header-summary cumulative deltas (plus the latest pack's header to close the last delta) to skip finalized idx packs holding ZERO entries of the selected feeds. - **`db_expire.go`** — `ExpireArticles(ctx, now)`: applies each feed's `ExpireDays` retention policy (root `CLAUDE.md` → Feeds `exp`/`xp`). Expiration clock is `fetched_at` — globally chron-monotone, so the expired set per feed is always a contiguous prefix, exactly what `AddIdx` models. One `walkArticles(min(AddIdx) → TotalArticles)` pass early-stopped by the `errExpireDone` sentinel at the first article with `fetched_at ≥ max(cutoff)`; an article expires iff strictly older than `now − ExpireDays·86400`. For each expired article the `assets/…` keys its content references are harvested by `collectAssetRefs` — `parseBodyFragment` + `visitAssetAttrs` (shared with `db_out.go`'s `rewriteAssetURLs`, so the attr set can't drift) with every candidate validated against the strict `assetKeyRe` grammar, not a bare prefix: the keys feed `Rm`, which path-joins on local/SFTP, so adversarial content like `assets/../victim` is never harvested (leak-safe, never delete-unsafe); unparseable HTML contributes nothing (it already published as-is — an error here would wedge retention forever). All-or-nothing: any walk, `Stat`, or `Rm` failure returns before ANY `AddIdx`/`Expired`/`AssetBytes` change is applied, so the next cycle recomputes the same window and retries idempotently (`Rm` is silent on missing). **Asset-bytes accounting**: every harvested key is `Stat`-measured BEFORE the delete loop (a stat failure aborts with nothing deleted; each phase fans out over a bounded errgroup — `max(1, globals.Workers)` — with the Wait between them preserving the no-Rm-before-every-Stat boundary), and each deleted object's size reduces the AssetBytes of the feed that first referenced it (`assetOwner`, chron-order deterministic), clamped at 0 (a mid-delete Rm failure loses the decrement for keys it did delete — the retry stats them as 0 — accepted skew). On success: `AddIdx` bumps past the expired prefix (logical deletion — packs/idx headers are immutable), `Feed.Expired` accumulates the count, and one INFO summary logs articles/assets/asset_bytes/feeds plus an `advanced` counter for the dormant-feed frontier advance: the walk records `stopChron` (the early-stop chron, else `TotalArticles`) and per-feed `sawLive`, and an expiring feed that saw no live own entry AND expired nothing this cycle jumps `AddIdx` straight to `stopChron` (the advanced-over region provably holds zero own entries — `xp` unchanged, the live-count cross-check holds; a feed that expired its tail waits one cycle), keeping the steady-state walk bounded by ingestion since the last cycle instead of growing with a dormant feed's dead time. **Liveness**: an expiring article's `assets/` keys are RELEASED in the asset reference sidecar (`asset_refs.go`) and only what reaches zero is deleted, so a shared object outlives its first expiring referrer; a key the sidecar covers but has no count for is KEPT and warned about. The one region still deleted with no liveness check is the pre-sidecar backlog (`chron < from`), which only drains. Each deleted object's bytes are released from the sidecar's recorded OWNER, which is what makes `ab` exact; `srr asset heal --create` remains the repair path for the residual cases. - **`cmd_compact.go`** — `CompactCmd` (`srr store compact`) + `DB.Compact(ctx, dryRun)`: the physical-compaction op (`docs/MANIFEST-SPEC.md` §9.2), the ONLY operation that removes bytes, deliberately **opt-in** (default off, `--dry-run` reports without writing; `--force` overrides the lock via the global) — never something a fetch cycle does silently. It reclaims the payloads of already-expired articles (`chron < feed.AddIdx`; a removed feed's orphans are NOT touched — content stays loadable, [DELETED] but present). It plans from the idx entries alone (feed_id + `AddIdx`), then rewrites each `data/` pack holding an expired line under a **fresh stem** (`compactDataPack`: expired line → `articleTombstone` keeping `f`/`a`/`p`, dropping `t`/`l`/`c`/`g` — the absent `c` is the reader's §9.3 "no longer stored" sentinel; survivors copied verbatim, so byte-identical), rewrites each `meta/` shard's expired cards to `{f,w}` (`compactMetaShard`/`tombstoneMetaLines`; a finalized shard's bloom rebuilt over survivors via `saveMetaShard`, the summary republished by `rebuildMetaSummary` under a fresh stem), leaves `idx/` untouched (so `total_art`/`next_pid`/`pack_off`/every feed's counts/the strides/`hsum`/every chron→pack mapping are unchanged — invariant M8, ZERO device-state migration), deletes the expired articles' `assets/` objects all-or-nothing BEFORE the flip (`rmAssets`; mostly a no-op — expiration deleted them already — so `AssetBytes` is deliberately left untouched, and the delete passes through the asset reference sidecar's liveness gate so compaction is not a quieter second path around "a shared object outlives its first expiring referrer"; it never decrements, since expiration already released those references, which is why a removed feed's id-reuse orphans are now KEPT rather than deleted), then adopts the staged name table (the SyncMeta clone idiom), runs `GC` and `Commit`. The live delta region is left untouched (its newest articles are essentially never expired; a rare expired delta payload compacts on a later run once it consolidates). A crash before Commit leaves the old (committed) packs intact and only orphan new objects — the universal crash argument §6.1. `srr inspect --validate`'s `checkChronPermanence` is the gate that proves no chron moved.
- **`feed.go`** — `Feed` carries one source URL plus its own fetch state: Title, `URL`, ETag/LastModified (both `json:"-"`, sidecar-backed), Watermark `wm` (reader-facing — displayed, and a partial dedup floor), BoundaryGUIDs `bg` (also `json:"-"`, in the dedup sidecar; reader-ignored), FetchError `ferr`, the vitals LastOK `last_ok`/FailStreak `fail_streak`/LastNew `last_new`, NoTitle `nt` (titleless microblog-style feed — the reader hides the article heading), Tag, Recipe `recipe`, the feed-level overrides Ingest `ingest`/Pipe `pipe` (each axis wins over the recipe when set — see Recipes), ExpireDays `exp` (0 = keep forever), server-owned Expired `xp` (cumulative expired-entry counter — readers subtract it from TotalArt), the server-owned byte counters ContentBytes `cb` (cumulative uncompressed JSONL bytes, bumped per article by `PutArticles`; monotonic — expiration is logical) and AssetBytes `ab` (live assets/ footprint: bumped by the stored payload size at upload — `uploadAssets` sums what `UploadCacheRef` reports for Puts it led, so dedup hits and singleflight followers add nothing — and reduced, clamped at 0, by expiration's deletes), TotalArt, AddIdx. `Feed.Fetch` resolves the recipe + `default` from `run.recipes` via `recipeFor`, the effective pipeline via `resolvePipe(resolvePipe(default.Pipe, recipe.Pipe), feed.Pipe)` and ingest via `ingest.Select(feed.Ingest, recipe.Ingest, default.Ingest)`, validates the pipeline, then calls `Feed.fetchURL`, setting/clearing `ch.FetchError`. `fetchURL` dispatches I/O+parse through the shared `*ingest.Fetcher`, then applies dedup/watermark/pipeline on `ingest.Result.Items`. **Dedup model**: `Watermark` is the max published unix-second ever seen and `BoundaryGUIDs` remembers as much of the current fetch's GUID window as the cap allows — so a feed that re-dates its whole window on every rebuild (fresh pubDates, stable GUIDs) still dedups: re-dated items always sit above the watermark, so the GUID memory has to cover them. Repopulated each non-empty fetch from the current response (snapshot, no carry-over), hard-capped at `maxBoundaryGUIDs` (1024) so one misbehaving feed can't bloat the sidecar (`bg` lives in the manifest-named `seen/` object — see the `db.go` bullet and `backend/SEEN-POOL-PLAN.md`). Two classes: **must** (dateless, or `pub >= maxPub` — the watermark will NOT skip these next fetch, so each must live in `bg` or be skipped from ingestion) and **opt** (`pub < maxPub` — watermark-protected in the stable case, remembered most-recent-first to survive re-dating, never skipped from ingestion). The `must` class is capped first, retaining already-stored (priorBoundary) GUIDs before the smallest-hash rest, so over-cap `must` items are skipped entirely rather than ingested-but-forgotten (which would duplicate them every subsequent fetch); `opt` fills remaining slots. A `NotModified` result or a non-modified response with zero items preserves prior `Watermark`/`BoundaryGUIDs`. An item is new iff its GUID isn't in the prior `BoundaryGUIDs` AND (`pub == 0` OR `pub >= Watermark`). Item `pub` is clamped to `fetchedAt` so a far-future publisher date can't poison `Watermark`. Within-fetch dedup uses a per-GUID set. **Stale-response guard**: a 200 whose newest dated item sits strictly below `Watermark` with no dateless items is a stale cache copy (flappy CDN — observed on YouTube's feed endpoint); ignored wholesale like `NotModified` (WARN; watermark/bg/ETag/LastModified preserved) — rebuilding `bg` from it would evict the watermark GUIDs and re-ingest duplicates one cycle later. Remaining trade-off: a response keeping one watermark sibling while dropping another (guard can't fire — its max pub equals `Watermark`), or dateless items that disappear for one fetch and reappear, still re-ingest as duplicates (snapshot semantics). Also hosts `resolvePipe`, the `#default` constant (`pipeDefault`), `maxBoundaryGUIDs`, the `fetchRun` struct (run-scoped deps incl. `recipes map[string]Recipe`), and `uint32Set`. (History: was `channel.go` until the Channel→Feed rename.)
- **`idx_layout.go` / `cmd_gents_layout.go` / `idx_layout.gen.go`** — the BINARY half of the contract, declared once. `idx_layout.go` holds `binLayout`/`binField` (field, width, byte order, count source: `countOne`/`countField`/`countArg`/`countRest`) and `idxLayout`, the idx pack's declaration — its widths ARE the db.go format atoms, so the constants the reader imports and the code both sides run come from one place. `cmd_gents_layout.go` is the emitter pair `srr gen-ts` drives: `emitGoLayout` → `idx_layout.gen.go` (geometry `idxHeaderEnd`/`idxEntriesEnd`/`idxHeaderSpan`, the `idxNumSlots` prefix peek, the shared `idxValidate` corruption wording, `idxDecode`/`idxDecodeFooter`, and `idxAppendHeader`/`idxAppendEntry`/`idxAppendFooter` — every count derived from the slice it counts, so a header can't claim a length its own bytes contradict), `emitTSLayout` → the binary-layout section of `format.gen.ts` (the same geometry + `idxValidate` + `idxDecodeHeader`/`idxDecodeEntries`/`idxDecodeFooter`; no encoder — the reader never writes a pack). `planLayout` hard-errors at generate time on any shape the emitters cannot express (a scalar after a variable-length field, a count source that is not an earlier scalar, an unsupported width, a footer whose length is not implicit) rather than emitting a parser that reads the wrong bytes. Consumers: `db_pack.go` (`writeIdxHeader`/`writeIdx`/`writeIdxFooter`/`parseIdxFooter`/`checkLatestIdx`/`readIdxHeader`), `idx_read.go` (`parseIdxPack`), the two header-summary walks (`cmd_inspect_check.go` `checkIdxSummary`, `db_out.go` `outPackSkipper`), and `frontend/src/js/idx.ts`. `idx_layout_test.go` pins the derived geometry against the format atoms and the generated encoders against `buildIdxRaw`, the hand-written independent spec.
- **`cmd_gents.go`** — `GenTSCmd` (`srr gen-ts`, hidden): generates `frontend/src/js/format.gen.ts` — the TS side of the writer↔reader data contract — and `idx_layout.gen.go` (`--out-go`), the Go side of the binary layouts; `--check` gates BOTH — by reflecting over the live Go declarations (the `tsConsts` table references the db.go format constants; `store.PackSeries` is emitted as the `PACK_SERIES_KINDS` grammar table; `tsTypes` walks the json tags of `ArticleData`/`MetaEntry`/`Feed`/`Recipe`/`OutFeed`/`DBCore`, omitempty → `?`, nil-able without omitempty → `| null`; emits `IArticleWire`/`IMetaWire`/`IFeedWire`/`IRecipeWire`/`IOutFeedWire`/`IDBWire`). `IRecipeWire`/`IOutFeedWire` are listed in `tsTypes` before `IDBWire` so the generator resolves the nested types; the frontend/service-worker ignores both. `//go:generate go run . gen-ts` (run via `make generate`); `--check` compares instead of writing and is wired into `make verify` (`verify-be`), so editing a format atom without regenerating fails loudly. A struct reachable from `tsTypes` but not listed in it is a hard generator error.
- **`cmd_config.go`** — `ConfigCmd` (`srr config`): prints resolved configuration. With no argument, prints all globals plus **every** registered backend section (http, s3, sftp — sorted, regardless of the active store scheme, so unset/inactive-backend configs are discoverable; secret-tagged fields mask through `maskSecret`, whose map case renders an empty `http.headers` blank and a populated one as the placeholder). A key argument prints a single field: a global name, a whole backend section by scheme (`s3`), or one backend field (`s3.region`) — all resolved against `store.Configs()`, not just the active store's scheme. Each line annotates its `[SRR_…]` env-override var **only when it deviates** from the conventional derivation (`expectedEnv`: `SRR_[<SCHEME>_]<SCREAMING_SNAKE(name)>`); a name the reader can derive from the field name is omitted. Backend env names are conventional by construction (`store.EnvName`), so they are never printed. When the `secrets:` section is set it is appended as a `secrets:` block (and resolvable via `secrets` / `secrets.<NAME>`), always **masked** through the shared `maskSecret` helper (`printSecretEntries`) so values never leak.
- **`cmd_frontend.go`** — `FrontendGroup` (`srr frontend`, alias `fe`) with one subcommand `update` (`FrontendUpdateCmd`): installs the prebuilt reader SPA into the store root so one origin serves reader + packs. Opens the store backend directly (`store.Open`, **no db.gz lock** — frontend files are orthogonal to packs). `resolveRelease` hits the unauthenticated GitHub API (`githubAPIBase` package var = test seam; `--repo`/`SRR_FE_REPO` default `gllera/srr`, `--tag` else latest), finds the `srrf.tar.gz` asset, `downloadAsset` (64 MiB cap) + `extractTarGz` (gzip+tar, regular files only, `cleanTarName` rejects absolute/`..`/nested names — the bundle is flat). `frontendUpdate` is the no-dangling reconcile: read `sitemap.txt` (`readSitemap`, ignore-missing) → write a **pending superset** manifest (old ∪ new) *before* uploading → `AtomicPut` each file (`mimeForKey` Content-Type; `uploadOrder` puts `index.html` last; abort on any upload error, leaving the old reader intact) → `Rm` orphans (old − new; a failed `Rm` is kept in `failed` and stays tracked, never dropped) → write the **final** manifest (new ∪ failed). Invariant: `sitemap.txt` is always a superset of the files present, so a crash anywhere self-heals on the next run. The published bundle's asset refs are relative but its pack base (`SRR_CDN_URL`) is the build-time absolute URL.
- **`processing.go`** — Per-item transformation utilities shared by `Feed.fetchURL` and `PreviewCmd`: `processItem` opens the item's **content session** (`mod.Module.NewSession`, see the Module System section) and drives the whole item through it, so the always-on steps and every DOM-form pipeline step share ONE parse; `absolutizeContent` rewrites the session's DOM in place (relative refs resolved against the item's own link, since the reader would resolve them against the pack base) and the language stamp reads the same DOM (`mod.DetectLangNode`). It then applies the **always-on language stamp** — filling `i.Lang` BEFORE the pipeline runs so pipe steps like `#filter keep_lang` can read it, in strict precedence **ingest-declared per-item `Lang` > confident detection > the feed's own declared language** (`feedLang`, the new `processItem` parameter carrying `ingest.Result.Lang`, normalised through `mod.NormalizeLangCode` so a junk `<language>zz</language>` stamps nothing — CON1; fail-open throughout: all three silent leaves it empty) — then runs the module pipeline, enforces GUID/Published immutability, normalises Title (via `bluemonday` strict policy + whitespace collapse), strips control chars from Link/Content, and re-attempts detection only when the pre-pipe pass produced nothing of its own **and the title/content it judged actually changed** (e.g. `#readability` replacing a teaser with the full body). "Nothing of its own" is `Lang == ""` **or** `Lang` still exactly the feed-declared fallback this call stamped: detection outranks the feed, so a grown body must be able to replace the fallback, while a value a pipeline step chose is left alone — and the retry only overwrites when re-detection returns a code, since assigning unconditionally would now clear a good fallback whenever it abstains too. The change guard tracks whether `DetectLang`'s inputs changed (title compared directly, content via `Session.Rev()` — a before-image would force the very materialization the session avoids), never their sizes — the gate is a rune count of extracted *text* while bytes are mostly markup, so a byte-heavy text-poor teaser replaced by a byte-light text-rich body is a genuine growth that shrinks; see `RawItem.Lang` in the Module System section. When a pipeline step sets `i.Drop=true`, `processItem` returns nil immediately and skips subsequent steps and post-loop normalization (the pre-pipe stamp has already run). Also hosts `validFeedURL` (used by `cmd_feeds.go` and `opml.go`).

### Ingest (`ingest/`)

An "ingest strategy" is the I/O+parse layer that produces `mod.RawItem`s from a URL; the default
zero-config behaviour is the historical one. Built-in names start with `#` and resolve through the
package's `Register` registry (init-time); anything not starting with `#` is an external command.
Mirrors `mod/`'s architecture — a `Fetcher` struct built by `New()` holds the registered built-in
`FetchFunc`s in a name→func map. `main.go` carries the `Request`/`Result` structs and the `FetchFunc`
type; `feed.go` is the built-in `#feed` strategy (HTTP GET with `If-None-Match`/`If-Modified-Since`);
`feed_discover.go` finds a feed link in an HTML page.

⚠ **The ingest engine owns no asset machinery** — it just sets the external command's working
directory to the run's shared cache dir, and SRR's end-of-pipeline step uploads whatever the command
left there. That division is why a strategy can self-host files without linking any SRR code.

**Full detail: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#ingest-ingest)**

### Store (`store/`)

Low-level storage interface: `Get`/`Stat`/`Put`/`AtomicPut`/`Version`/`PutIfVersion`/`Rm`/`Close`. Registry selects by URL scheme; local = empty scheme `""`. Config registry: backends call `RegisterConfig` in `init()` with a config struct pointer; `LoadConfigs` reads YAML sections into them. `main.go` also owns the write-once pack-name grammar: the `PackSeries` series→kinds table (the contract's single source — emitted to the frontend as `PACK_SERIES_KINDS` by `srr gen-ts`) builds `packKeyRe`, which `cacheControlForKey` uses to stamp immutable Cache-Control on pack keys (strict per-series: `data/h3.gz` is not a pack name). `cacheControlForKey` also revalidates `db.gz` and `config.gz` (the two mutable roots), and classifies the self-hosted frontend shell at the store root (`srr frontend update`): `index.html`/`manifest.webmanifest`/`sitemap.txt` revalidate, content-hashed root assets (`feHashedRe` = `<name>.<8+ hex>.<ext>`, slash-free so it never matches a pack key) are immutable. Its sibling `contentTypeForKey` stamps the meta-unset Content-Type the same grammar-driven way: `db.gz` + `config.gz` + `inbox/` + `packKeyRe` matches → `application/gzip` (honest type for SRR's own gzip objects; deliberately NO `Content-Encoding: gzip` — the reader gunzips manually via `DecompressionStream`, so a transparently-decompressing CDN/browser would hand it pre-inflated bytes and break it), everything else `application/octet-stream`. S3 + HTTP backends only (local/SFTP ignore Cache-Control/Content-Type, deferring to the static server's mime-by-extension).

| Method | Signature | Behavior |
|---|---|---|
| `Get` | returns `io.ReadCloser` | Streaming read; a missing key is an error wrapping **`fs.ErrNotExist`**. The `ignoreMissing` flag is retired — it lived in each of four backends, so each decided for itself what counted as absence and answered `(nil, nil)`, a shape in which a timeout and a 404 are the same value. Callers whose absence IS a legal state (no root yet, no config sidecar, no lock marker) go through the one caller-side `getOptional` helper in `db.go`; everything else lets the error propagate |
| `Stat` | returns `int64` | Object size without reading the body (os/sftp stat, S3 HeadObject — its missing-key code is the bodyless `NotFound`, not `NoSuchKey` — HTTP HEAD); a missing key is an error wrapping **`fs.ErrNotExist`** — so a nil error PROVES presence, which is what lets the upload dedup probe (`resolveAndUpload`) settle existence in one bodyless call instead of falling back to a body-carrying `Get` whenever the size read 0 (a zero-byte object and a HEAD without Content-Length both do). A size of 0 with a nil error is a legal answer, never absence. Callers wanting absent-as-zero say so explicitly with `errors.Is` (expiration's AssetBytes accounting, so a retried expire cycle can re-stat keys an aborted predecessor already deleted) |
| `Put(ignoreExisting)` | accepts `io.Reader` | Controls overwrite vs exclusive create; streaming write |
| `AtomicPut` | accepts `io.Reader` | temp-then-rename (local/SFTP); overwrite (S3); streaming write. Local/SFTP also sweep stale `<key>.tmp.<pid>.<n>` staging leftovers in the target's directory (age-gated `tempSweepMaxAge` 24h via `staleTemp`, best-effort): a hard kill between temp-create and rename strands a uniquely-named file no GC speaks, so without the sweep each such crash leaked one store file forever. The sweep runs *after* the call's own staging file is created and ages leftovers against **that file's** mtime read from the same directory listing, never `time.Now()` — both sides of the comparison must come from the store's clock, which on an SFTP server or an NFS/SMB mount is not this host's (and taking the reference from the listing costs no extra round-trip). Our own entry is skipped, and a missing reference or a zero mtime (a server omitting it in READDIR attrs) means no sweep at all: no reference, no judgement. The gate is what protects a live writer's in-flight temp, and concurrent asset uploads inside ONE process already put several in a shard |
| `Version` | returns `string` | An OPAQUE token for the key's current content, `""` when absent, `errors.ErrUnsupported` when the backend has none. Meaningful only as an argument to `PutIfVersion` — nothing parses it or compares tokens across backends. For small MUTABLE roots (`db.gz`) only: a backend may READ the object to answer |
| `PutIfVersion(want)` | returns the NEW version | `AtomicPut` with a precondition — the write lands only while the key's version still equals `want` (`""` = must not exist). Returns the stored object's new token, so a caller holding it across writes never re-reads. A lost race is `ErrPreconditionFailed` with the object untouched; `errors.ErrUnsupported` when the backend cannot express the condition |
| `Rm` | — | Silent on missing (local/SFTP warn + return nil; S3 unconditional delete) — the ONE deliberate exception to the fs.ErrNotExist contract, since deleting an absent key IS success |
| `RmAll(keys, parallel)` | returns `(failed []string, err error)` | Package helper, not a method: a bounded errgroup fan-out over `Rm` (deliberately NOT `errgroup.WithContext` — one key's failure must not cancel its siblings), preferring a backend's `BatchRemover` override where it has one (S3 → `DeleteObjects`, 1000 keys/call, per-object errors mapped back to logical keys, falling back to per-key `Rm` on `NotImplemented`/`MethodNotAllowed` so a gateway without the multi-delete verb can't wedge warn-only retention forever). `failed` is the keys STILL in the store, so successes are implicit and never rolled back — which is what lets the GC advance `gcm` only over generations that fully cleared while keeping the deletes that landed |
| `List(prefix)` | returns `[]string` | Store-relative keys under a plain string prefix, lexicographically sorted (both filesystem backends sort explicitly — walk order is not lexicographic over joined keys). A prefix matching nothing is an empty slice + nil error, NEVER `fs.ErrNotExist`: a prefix names a set, not an object. `errors.ErrUnsupported` on HTTP, which has no portable listing verb — callers keep their fallback (GC its low-water drain, `srr frontend update` its sitemap) |

- **`local.go`** — Auto-creates subdirs via `os.MkdirAll`. `Version` DIGESTS the file's bytes: a filesystem exposes no entity tag and every cheap surrogate (size, mtime, inode) lies on some filesystem or other, and content-addressing has no ABA hazard for the one key that uses it (the root's generation counter is monotone — it can never come back to bytes it already had). `PutIfVersion` is therefore BEST-EFFORT (check, then rename): it narrows the window from the whole cycle to the rename instant, on a store that is one filesystem on one host and already serialized by the leased `.locked` marker plus the exclusive-create manifest publish. The real compare-and-swap is `s3.go`'s.
- **`s3.go`** — `IfNoneMatch` precondition headers + CRC32 checksums. `S3Config`: region, endpoint, profile, static credentials. `Version` = the object's ETag (HeadObject) and `PutIfVersion` = `If-Match` (or `If-None-Match: *` for "must not exist") on PUT, both 412 → `ErrPreconditionFailed` — a REAL compare-and-swap, on the backend the production store runs (R2) and the one the root flip needed it for.
- **`sftp.go`** — Auto-creates subdirs via `client.MkdirAll`. **Sessions are memoized** (`sftpSessions`, the `s3Clients` shape) keyed on a composite `sftpSessionKey{cfg, addr, user, urlPassword}` — the URL password is IN the key because the auth chain prefers it over `SFTPConfig.Password`, so two stores under different credentials can never share a session. A lookup liveness-probes with one `Getwd` and drops-and-redials a dead entry; the dial happens under the mutex so concurrent Opens share one handshake. `dialSFTPSession` is the test seam. **`Close()` is a handle release that never tears the shared session down** — the memo owns teardown, and a session dies only when a later lookup's probe finds it unresponsive. Before this, `newSFTP` paid TCP + SSH handshake + subsystem on EVERY `store.Open`, i.e. once per serve API request. Mid-operation recovery is `sftpSessionRefresh` (the other half of the probe): it re-probes under the memo lock and replaces the session only when it is really dead AND still the memoized one, so a session serving other handles is never torn down on one op's suspicion and a parallel `RmAll` redials once rather than N times. `Version`/`PutIfVersion` are the same content digest + best-effort check-then-rename as local, and for the same reason (an SFTP server exposes no entity tag either, and its clock is not this host's). Auth chain: URL password → config password → config/default private key → `~/.ssh/` keys → SSH agent → error. Host key verification via `~/.ssh/known_hosts` by default (`SFTPConfig.Insecure` to skip).
- **`retry.go`** — `withRetry`/`withRetryBody`: 3 attempts, exponential half-jittered backoff, wrapping SFTP and HTTP's `Get`/`Stat`/`Rm`/`List`/`Version`/`AtomicPut`/overwrite-`Put` (S3 keeps the SDK retryer, local needs none). Retries **connection-class errors only** — `net.Error` timeout, ECONNRESET/ECONNABORTED/EPIPE, `net.ErrClosed`, a pre-response EOF, `sftp.ErrSSHFxConnectionLost`. Never retried, by construction: `fs.ErrNotExist` and `errors.ErrUnsupported` (definitive answers), `ErrPreconditionFailed` (the root-flip CAS loser — a replay would publish over a peer's generation), `os.ErrExist`, ctx cancellation, and anything else. ⚠ **`context.DeadlineExceeded` is itself a `net.Error` reporting `Timeout() true`**, so the cancellation check MUST run before the timeout arm — that ordering is load-bearing. Two things are deliberately NOT retried: an **exclusive-create `Put`** (the `.locked` lease acquire — a repeat after a PUT that landed before the connection broke would see its OWN marker and self-deadlock; excluded at the call site *and* inside `retryable`), and **a write whose body cannot be proven replayable** — SFTP retries iff the attempt read zero bytes or the source seeks back to its starting offset, HTTP iff `req.GetBody != nil`; a partly-read unrewindable body (a streamed `*os.File` asset) ends the retry rather than risk a truncated pack under an immutable, cached-forever key.
- **`http.go`** — Plain HTTP object store (WebDAV-style / S3-compatible endpoint), registered for both `http` and `https` schemes (one shared `http` config section): `Get`=GET (404/410 → missing), `Put`/`AtomicPut`=PUT (AtomicPut is a plain overwrite like S3; metadata rides request headers — Content-Type from meta, then `contentTypeForKey` (db.gz + seen slots + pack names → `application/gzip`), then the `application/octet-stream` default; Content-Encoding only when meta sets it; Cache-Control from `cacheControlForKey` — servers that don't store metadata serve their own headers like local/SFTP), `Rm`=DELETE (404/410 → nil), `Stat`=HEAD (size from Content-Length, -1/absent clamped to 0 — a PRESENT object of unknown size; 404/410 → `fs.ErrNotExist`). Exclusive create maps to `If-None-Match: *` with 412 wrapped in `os.ErrExist` (the lock/409 contract); a server that ignores conditionals makes `.locked` best-effort. `Version`/`PutIfVersion` return `errors.ErrUnsupported` — a judgement, not an omission: a WebDAV-ish endpoint may return an ETag and ignore `If-Match`, with no in-band way to tell, and a conditional write that silently degrades is worse than none (the caller believes it holds a guarantee it does not). `DB.flipRoot` falls back to the unconditional `AtomicPut` on exactly this signal. Auth: URL userinfo (net/http basic auth), `HTTPConfig.Token` (bearer), or `HTTPConfig.Headers` (extra headers on every request, e.g. Cloudflare Access service tokens; an explicit `Authorization` entry wins over Token; both secret-tagged — the map masks whole via `maskSecret`'s map case. `SRR_HTTP_HEADERS` env-overrides it through `loadEnv`'s `map[string]string` case (`parseEnvMap`: comma-separated `Name: value` entries, split on the first colon, trimmed; replaces the YAML map whole)); `Insecure` skips TLS verification. **Own transport**: the backend uses a per-config cloned `*http.Transport` (`httpTransportFor`, keyed on TLS verification alone — Token/Headers are per-request and must not fork a pool), so `Close()` no longer calls `CloseIdleConnections()` and can't flush every other `DefaultTransport` user's keep-alives process-wide. **Redirect guard**: `CheckRedirect` follows redirects only when the original request was a GET or HEAD (`Stat`) — net/http otherwise silently replays a 301/302/303-redirected PUT/DELETE as a bodiless GET and reports the GET's status, turning a write that never happened into a false success (found by conformance audit; pinned by `TestHTTPWriteRedirectFailsLoudly`). No client timeout by design (uploads may run long; every op carries the caller's ctx); URLs log via `Redacted()` so userinfo passwords never leak. One shared `http` config section for both schemes (no `SRR_HTTPS_*` names, deliberate).

### Pack Storage (`db.go` + `db_pack.go` + `db_meta.go`)

See root `CLAUDE.md` Data Contract for the pack formats (idx/, data/, meta/), the root/manifest/config-sidecar schemas, the CDN layout, and the two advisory locks. The commit model itself is `docs/MANIFEST-SPEC.md`.

Split across four files by concern:
- **`db.go`** — `DB`, `DBCore` (in-memory state, not a wire type), `Recipe`, `OutFeed`, lifecycle (`NewDB`/`Close`/`Commit`), feed CRUD (`AddFeed`/`RemoveFeed`/`FeedByID`/`Feeds`), `withDB`/`withDBCtx` boilerplate wrappers, and shared utilities (`gunzip`, `readGz`, `jsonEncode`). `Commit` is the three-step publish (config sidecar when it changed → the immutable manifest, exclusive-create → the root flip); `DBCore` is in-memory state only and is never itself serialized. `DBCore.Recipes`/`Out`/`DedupDays` are the store-wide config half, loaded from and written to `config.gz`. `defaultRecipeName = "default"` is the reserved fallback; `recipeFor(recipes, name) Recipe` resolves an empty or unknown name to `default`. `NewDB` resolves the root, merges `config.gz` onto the feeds, seeds the `default` recipe (`["#sanitize","#minify"]`) when absent, loads the seen sidecar the manifest names (`db.seen = db.loadSeen(ctx)`), hydrates each feed's `ETag`/`LastModified`/`BoundaryGUIDs` from it, loads the asset reference sidecar beside it (`db.refs = db.loadRefs(ctx)` — never fails an open), and — on a LOCKED session against a pre-cutover store — migrates. Also holds the format atom constants including `searchGram`/`searchBloomBytes`/`searchBloomK` (exported to TS as `SEARCH_GRAM`/`SEARCH_BLOOM_BYTES`/`SEARCH_BLOOM_K` by `cmd_gents.go`) and `metaPackSize` (exported as `META_PACK_SIZE`).
- **`db_pack.go`** — Binary idx + JSONL data pack writer. Contains `ArticleData` and `Item` types (plus `Item.articleData`, the one Item→ArticleData mapping), the `pack` struct (`newPack`/`writeIdx` — a 2-byte entry `feed_id:u16 LE` — /`writeIdxFooter`+`parseIdxFooter` — the data-pack boundary footer, u16 LE local indices where the packId advances; `parseIdxFooter` recovers it on the append path — /`writeIdxHeader` — the variable-length header: 2 state u32s (`packId_base`, `packOff_base`) + a `numSlots` u32 prefix, then `numSlots` cumulative-count u32s sized to the high-water feed_id present /`writeArticle`), `loadPack` (returns the decompressed bytes; `packFromBytes` wraps them into an appendable pack, guarding the empty case so a fresh store keeps `Len()==0`), `savePack`/`savePackFinal`/`checkLatestIdx` (`checkLatestIdx` verifies the latest idx pack's entry count against db.gz and returns the entries-end offset the append path splits the footer at; `savePackFinal` publishes finalized — immutable, downloaded-forever — names recompressed by `gzipBest`: zopfli-grade deflate via `foobaz/go-zopfli`, still plain gzip to readers, measured −4% data / −11% idx; the candidate must round-trip byte-for-byte through the stdlib gzip reader or the save hard-fails — no silent fallback, a finalized name is cached forever so corrupt bytes must never publish. Latest packs, summaries, and db.gz keep fast stdlib gzip. `finalGzip` is the test seam — `setupTestDB` stubs it to identity so 50k-boundary tests skip the CPU), and the `PutArticles` driver (returns the `[]ArticleData` it persisted, in pack order — `SyncMeta` consumes that slice so derived meta cards can't drift from the packs). Also `dataKeyFor` and `parseDataPack`/`splitDataPack` (`parseDataPack` streams a data-pack buffer to `[]ArticleData` for `cmd_art.go`/`cmd_inspect.go` read-side access; `splitDataPack` additionally returns each entry's verbatim JSONL line bytes, used by the memoized `loadDeltaChain`/`loadDeltaArticles` so consolidation re-emits delta bytes without a re-encode), and the idx header-summary machinery: `numFinalizedIdx`/`idxKeyAndSize` (key from the manifest's name list, size from chron arithmetic)/`readPackHeader` (fixed-size header reader, used by meta's bloom header)/`readIdxHeader` (variable idx header: reads the prefix, then `numSlots`×4 count bytes), `saveSummary` (concatenates finalized-pack headers under a caller-chosen key; takes a per-pack header-bytes callback so idx passes its variable-header reader and meta passes its fixed bloom reader), and `SyncIdxSummary` (rebuilds the summary from the finalized packs' headers whenever the published coverage lags, under a FRESH stem, recording `names.hsum = {stem, covers}` only after the save succeeds).
- **`db_meta.go`** — Meta pack writer and folding contract. `MetaEntry` type (`f`/`w`/`t` JSONL wire — the struct tags own the format; every encode and decode goes through it) with its buffer-level decoder `parseMetaEntries` (used by `srr inspect`'s `checkMeta` and the tests). `foldSearchText` (NFD → strip Mn → lowercase → ς→σ → non-letter/number = word break, space-joined; mirrored by `search.ts fold()`). `bloomBits`/`bloomAdd`/`bloomHas` (FNV-1a-64 double-hash, 7 probes, mask `& (2^15-1)` matching `searchBloomBytes`=4096). `walkArticles` (streams `[from, to)` chron range: idx+data packs below `tailCovered`, the parsed delta chain at/above it). `SyncMeta(ctx, written)` (called by `cmd_fetch` between `SyncIdxSummary` and `Commit` with the `[]ArticleData` slice `PutArticles` returned, warn-only): covers the CONSOLIDATED region only (`target = tailCovered`; delta cycles no-op — the chain's cards ride the reader-resident deltas, accounted by `na` in the coverage gate) — reads back the previous tail (the key the manifest currently names, or `o.prevMetaTail` on a consolidation cycle; trusted iff entry count == `MetaTail`), fills the missing range from `o.consolidated` (the replay slice) or `written` (only when `na==0` — a live chain's batch is delta-region content) when either covers the gap exactly, else via `walkArticles`, finalizes bloom-headed shards at `metaPackSize`=5000 boundaries (`saveMetaShard`), writes the new tail shard, rebuilds the bloom summary when the finalized count moved; STAGES every name change on a clone of the table and adopts it — with `MetaTail` — only after every save succeeds, and refreshes the head projection only when it wouldn't regress past a delta-maintained head. The meta/ series feeds BOTH the home list (with a data/ fallback when `metaReady()` is false, so warn-only is safe even though the list depends on meta) and search. `golang.org/x/text` (unicode/norm) is a direct dependency.
- **`idx_read.go`** — the single Go read-side mirror of the binary idx format: `keyGetter` (fetch+gunzip a store key, local or HTTP), `idxPack`/`idxBound`, `parseIdxPack` (the BYTES come from the generated `idxDecode` — see `idx_layout.go` — so what mirrors frontend `idx.ts` `makeIdxPack().parse()` is the semantics on top: the store high-water `ownFeedCounts` sizing and the bounds walk), `getPackRef` (mirrors `data.ts`), `packIdxFor`, plus the delta chain: `parseDeltaChain` (THE chain reader — fetch the listed segments oldest-first, `splitDataPack` each, enforce non-empty segments + `Σ lines == na`; the writer's memoizing `DB.loadDeltaChain` and the read side's `loadDeltas` are both thin wrappers over it, where they used to be near-identical copies), `loadDeltas` (the articles-only view inspect and art take), `loadLatestIdx` (extends the physical `L<tailGen>` pack with the chain's feed ids and a sentinel bound `{deltaPackID = −1, tailCovered}`; synthesizes an empty base for an all-delta store), and `loadIdxPacks` (returns `(packs, deltas, err)` — delta-region `getPackRef` hits resolve `deltas[offset]`, never a data pack). Every read-side command (`srr inspect`, `srr art`) goes through this one parser; the only other implementations of the format are the writer (`db_pack.go`) and the frontend reader.

**Delta-segment tail** (2026-07-17, spec `docs/DELTA-TAIL-SPEC.md` — read it before touching this): `PutArticles` is split into an **accounting preamble** (TotalArticles / per-feed TotalArt / ContentBytes, once per article at ingest) and a materialization path chosen by `shouldConsolidate`. An oversized batch is first **chunked** (`--max-batch-bytes`/`SRR_MAX_BATCH_BYTES`, default `maxBatchBytesDefault` 32 MiB, 0 = off): encoded, accounted and driven through `putBatch` in sub-batches of at most the cap's JSONL, so a backfill's transient memory follows the cap — byte-invisible in the store, pinned by `TestChunkedBatchEquivalence` (comparing raw objects by POSITION, stems excluded). Chunking exposed a latent nondeterminism in `packFromBytes`: `pack.Len()` is the COMPRESSED length and flate steps its encoder once per `Write`, so replaying a reloaded tail in one `Write` under-reported until the next write — the roll point depended on consolidation history. It now replays one JSONL line per `Write`, the same granularity the materialization loop appends in (published bytes never depended on this; only the in-flight `Len()` did). Then the path proper — chain cap `--max-deltas`/`SRR_MAX_DELTAS` (default `maxDeltasDefault`=12, exported as `MAX_DELTAS`; **0 = kill switch, byte-identical pre-delta behavior** — what the zero-value test globals run), byte cap `--max-delta-bytes` (`dby` tracks it), or a 5k-meta-stratum crossing (invariant I2). A **delta cycle** (`emitDelta`) first re-validates the consolidated tail idx (`checkTailIntact` → `checkLatestIdx` against `tc`; warn on a transient read, fatal on a structural mismatch — a corrupt tail fails loud NOW instead of at the next consolidation ~maxDeltas cycles later), then publishes the batch as an immutable object under a FRESH data-series stem, appends it to `names.deltas`, bumps `na`/`dby`, and maintains the head projection itself (`DBCore.extendHead` — SyncMeta no-ops, `tailCovered` unmoved). A **consolidation cycle** (`consolidateTail`) parses the chain via the memoized writer-side `loadDeltaChain` (keyed on the chain's own identity — segment count + newest stem, exact under write-once names; the body is the shared `parseDeltaChain` in `idx_read.go`, returning parsed arts + verbatim JSONL line bytes; `loadDeltaArticles` is the arts-only view `walkArticles` uses, so ExpireArticles/SyncOutFeeds/SyncMeta+consolidate share ONE fetch/parse per cycle) and replays deltas ++ batch through the classic materialization loop — ⚠ threading an **as-of-chron count vector** for `writeIdxHeader` (seeded `liveCounts` minus unreplayed occurrences; accounting already ran in the deltas' own cycles), and writing each data-pack entry as its **pre-encoded** line bytes instead of re-encoding — byte-identical since `jsonEncode` is deterministic, pinned by `TestConsolidationEquivalence` (delta_test.go) against the kill switch — then writes the new tail packs under fresh stems, records them in the name table only after BOTH saves succeed, and clears the chain. `DrainDeltas` = batch-less consolidation + warn-only SyncMeta; **`RemoveFeed(ctx, id)` drains the chain ONLY when the removed feed has an entry in it** (an id freed while its dead incarnation's articles sit in a live chain, then reused, would corrupt replayed headers — the format-review HIGH). A dormant feed with no chain entry is removed with NO consolidation — membership is checked by only READING the chain (`loadDeltaChain`), and only an unparseable chain blocks removal. `tailCovered(core) = TotalArticles − na` is the pack↔delta seam (`idxKeyAndSize` returns the PHYSICAL tail size; callers extend with the chain). Reclamation is the store-wide `GC` rule and nothing delta-specific: a live segment is named by the manifest this cycle publishes, so it is reachable by construction at any `--max-deltas` (which retired the spec's two hand-derived GC horizons — `docs/DELTA-TAIL-SPEC.md` §8, superseded).

Backend-specific behavior:
- `PutArticles` and `savePack` manage the idx and data series. `SyncMeta` manages the meta/ series, `SyncWatch` the watch/ series. Order: `PutArticles` → `SyncIdxSummary` → `SyncMeta` → `SyncWatch` → `ExpireArticles` → `SyncOutFeeds` → `SyncSeen` → `SyncRefs` → `GC` → `Commit`.
- Consolidation writes binary idx and JSONL data directly; splits idx packs at every 50,000 articles (accounting — each article's uncompressed JSONL line length charged to its feed's `ContentBytes` — lives in `PutArticles`' preamble). It tracks the data-pack boundaries (where `NextPackID` advances) into a per-pack slice and emits them as the idx footer at each finalize and at the tail-pack save; on the append path it strips the loaded tail pack's old footer (keeping header+entries) and recovers its boundaries via `parseIdxFooter` before extending.
- `ArticleData` struct: `{ FeedID, FetchedAt, Published, Title, Link, Content, Lang }` — serialized as JSONL with short keys `f/a/p/t/l/c/g` (`Lang` = `g`, omitempty — from `Item.Lang`; see `RawItem.Lang` in the Module System section). An absent `g` means "unknown": the fail-open detection stamps nothing on uncertain articles, and every article written before 2026-07-19 predates the field (packs are immutable, so old lines are never backfilled).
- `DBCore.Feeds` is `map[int]*Feed`; serialized as a JSON object keyed by feed ID. `AddFeed` assigns the first free ID in `[0, feedIDCeiling)` (`feedIDCeiling` = 65536, since `feed_id` is a u16 in each idx entry) and returns an error if all slots are taken; it sets `AddIdx = TotalArticles` and explicitly zeroes `Expired` (a fresh incarnation has expired nothing — a reused id's legacy entries sit below the new `AddIdx`, keeping the id-reuse invariant local by construction). `NewDB` range-checks loaded ids and rejects a feed with an empty `URL` (a pre-merge `feeds[]`-only db.gz) with a delete-and-re-fetch message. `RemoveFeed(ctx, id)` first drains a live delta chain (`DrainDeltas` — see the delta-tail paragraph above), then `delete`s and purges the seen sidecar state.
- Every object name comes from the manifest's name table and nowhere else (`names.go`): each series draws stems from a monotone counter that is never reused, the table lists them positionally, and `Commit` publishes the table with the batch. A name can never be seen half-written, rewritten, or reused, which is why there is no cache-invalidation signal (`gen`) and no purge discipline left to observe.
- `SyncIdxSummary` and `SyncMeta` still run between `PutArticles` and `Commit`, still warn-only (a failed derived index must never discard a durable batch; readers fall back to eager idx loading / the `data/` source of truth, and the next run retries). What they no longer carry is a publish-order proof of their own: each writes new immutable objects and records their names, and the ONE crash argument in `manifest.go` covers all of them.
- `withDB(locked, fn)` / `withDBCtx(ctx, locked, fn)`: most cmd `Run()` methods are now a single `withDB` call wrapping the work.

### Module System (`mod/`)

Pipeline per-feed during fetch. Factory pattern: `New()` returns a fresh stateful processor; each
built-in registers a `func() Processor`. **Two step forms share one namespace** (`session.go`, FET11):
a built-in that walks HTML registers a `mod.DOMProcessor` and runs against the cycle's ONE parsed DOM
session, while anything else stays a plain `mod.Processor` over the string — so a chain of DOM mods
parses and serializes once, not once per step. **File layout**: `main.go` holds the engine (registry +
`Module`/`Process` dispatch), the `RawItem` wire types, and the external/subprocess path; each built-in
gets its own file. **Module parameters**: a pipeline token may carry `key=value` options after the name
(e.g. `#readability timeout=30s maxbody=16MiB`).

Built-ins: `#sanitize` (bluemonday, content-only), `#minify`, `#readability` (full-text fetch for
teaser-only feeds), `#filter` (content-based item dropping), `#dedupmedia`, `#unlazy`, `#embed`,
`#enclosure`, `#untrack`, `#selfhost`. Plus `mod.ParseMatch`/`mod.Match` (`helper_match.go`) — not a
pipeline mod, but the compiled per-article predicate the keyword watchlist and `#filter` share.
External modules are `/bin/sh -c` with stdin/stdout JSON (`RawItem`) and stderr passthrough.

⚠ Contracts that bind every module, built-in or external: **`GUID` and `Published` are immutable**
(a change is an error, enforced in `processItem` after each step); `RawItem.Drop` signals removal;
`RawItem.Lang` is the ISO 639-1 code persisted to the data packs. Asset self-hosting
(`assetFetcher.UploadCacheRef` + `RewriteAttrs`, incl. `SRR_ASSET_PROCESS` and `SRR_ASSET_PEEK`) is
documented in the companion file with the rest.

**Full detail: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#module-system-mod)**

### Recipes

Processing config lives in named `{ingest, pipe}` recipes (`DBCore.Recipes map[string]Recipe`), referenced by feeds via `Feed.Recipe`. The reserved `default` recipe (always present, seeded `["#sanitize","#minify"]` by `NewDB`) is the fallback.

- A feed with empty/absent `Recipe` resolves to `default` via `recipeFor`.
- Each axis falls back to `default` independently: a recipe with only `Ingest` set uses its own ingest and `default`'s pipe; only `Pipe` ⇒ its pipe and `default`'s ingest.
- **Feed-level overrides**: `Feed.Ingest` (`ingest`) and `Feed.Pipe` (`pipe`) sit on top of the recipe, each axis independently — set, they win over the recipe's value; empty, they inherit it. Resolved at the start of `Feed.Fetch`: `resolvePipe(resolvePipe(default.Pipe, recipe.Pipe), feed.Pipe)` and `ingest.Select(feed.Ingest, recipe.Ingest, default.Ingest)` (variadic first-non-empty).
- `#default` (`pipeDefault`) expands inline to the next pipe down the fallback chain: in a recipe's pipe, the `default` recipe's pipe; in a feed's pipe, the feed's *effective recipe pipe* (already `#default`-expanded). The `default` recipe itself forbids `#default` (enforced by `validatePipe(allowDefault = name != defaultRecipeName)` in `RecipeSetCmd`); a feed pipe always allows it (`normalizeFeed` runs `filterPipe` + `validatePipe(…, true)`).
- CLI: `srr recipe set <name> [-i ingest] [-p step]…` (add/replace); `srr recipe ls/show/rm`; `srr feed add/upd/import -r <name>`; feed-level overrides via `srr feed add/upd [-i ingest] [-p step]…` (on `upd`, `-i ""` clears the ingest override and a lone `-p ""` clears the pipe override). Every `-p` flag is **repeatable, one step per flag** (`sep:"none"`).
- Clean break, amended: a pre-recipes db.gz's legacy **root** `pipe`/`ingest` still drop on load (DBCore has no such json tags) and `NewDB` re-seeds `default` if absent — but the legacy **feed-level** keys are the same keys `Feed.Ingest`/`Feed.Pipe` use today, so those values revive as feed-level overrides (deliberate: the old per-feed meaning matches the new one; pinned by `TestNewDBLegacyPipeIngest`).

## Conventions

- **Imports**: stdlib → external → internal, blank-line separated, alphabetical within groups
- **Errors**: Always wrap with `fmt.Errorf("context: %w", err)`. No custom error types; the only package-level sentinels are `errNotFeed` (`ingest/feed.go`), `errNotAsset` and `errCorruptAsset` (`assets.go`), `errExpireDone` (`db_expire.go` — the expiration walk's early-stop channel, since `walkArticles`' callback contract has no other), and `store.ErrPreconditionFailed` (`store/main.go` — the conditional-write loser, the signal that turns a silent last-write-wins into a loud retryable abort) — don't add more without need.

## Constraints (preserve when editing)

- File-based DB lock (`.locked`) with `--force` override — a LEASE (`lock.go`): `{owner, expires}`, reclaimed when the owner is this process instance, stolen once expired, refused otherwise (and always refused for a payload-less legacy marker). **`leaseTTL` must exceed the longest possible cycle, as correctness and not headroom**: a steal only guarantees the ROOT is never double-flipped, and two live writers draw the SAME stems and overwrite each other's pack objects. See root `CLAUDE.md` → File-Based Locking
- The root flip is a compare-and-swap (`DB.flipRoot` + `Backend.PutIfVersion`); a lost race ABORTS the cycle loudly rather than publishing over a peer's generation
- Env vars prefixed `SRR_`
